

Структура БД:
Requestor подает заявку
В заявке может быть несколько Work Centers
В рамках одного Work Center может быть забронировано несколько единиц техники
Техника принадлежит одному Fleet
Fleet может иметь несколько техник
Fleet-ом владеет Fleet Owner
(Все что связано с техникой, флитами, флитоунерами будет в отдельных БД ресурсов и human resourses)

И, тогда структура БД Booking tool будет:

**BookingRequests**
- id
- createdAt
- createdBy
- updatedAt
- UpdatedBy
- deletedAt
- isDeleted
- type (regular, service work)
- status (draft, submitted, in progress, etc.)
- workOrder 
- workOrderDescription
- workOrderstatus
- priority (P1-P4)
- location
- comments
- requestorId
- дополнить

**WorkCenters**
- id
- code (LRG, MGT, BHOE, etc.)
- requestId

**Booking**
- id
- workCenterId
- equipmentId

**dicWorkCenters**
- id
- code
- name

Сами equipment-ы, fleet-ы будут в своей бд resourses

Или таблица WorkCenters не нужна?
Избыточна?
Прикол в том, что в одной заявке пользователи могут назначать несколько "Рабочих центров" (их еще называют "шагами", потому что эти рабочие центры выполняются последовательно). А в рамках рабочего центра уже собирается нужная техника.

Можно сделать и так:
**Booking**
- id
- equipmentId
- workCenterCode

И тогда как будто таблица WorkCenters особо не нужна.
