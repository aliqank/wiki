# Рабочие правила

## Язык и стиль
- Общение с пользователем — на **русском языке**
- Технические термины из BRD сохранять как есть (Fleet Owner, CC Owner, SWR, RWA, SLA и т.д.)
- Ответы краткие и структурированные; таблицы и блоки кода — там, где повышают читаемость

## Сохранение результатов
- Все результаты сохранять в папке `Результаты claude/` в формате `.md`
- Имя файла: `YYYY-MM-DD - <краткое название темы>.md`
- В начале каждого документа указывать:
  - **Дата создания:** YYYY-MM-DD HH:MM
  - **Последнее обновление:** YYYY-MM-DD HH:MM
  - **Автор:** Тельман Нуржанов (SA)
- Перед созданием файлов других форматов (.bpmn, .xml, код и т.п.) — спрашивать пользователя

## Навигация по проекту
- **Сначала открывать `Список материалов.md`** в корне проекта — там перечислены все файлы с описаниями
- По описанию определить нужный файл и читать именно его
- Сканировать остальные файлы только если нужное не найдено в списке
- При добавлении новых файлов — обновлять `Список материалов.md`

## Работа с требованиями
- При анализе требований учитывать AS-IS процесс (из транскрипций встреч)
- Фиксировать открытые вопросы и TBD-пункты отдельно
- Структура документов: контекст → AS-IS → TO-BE → сущности → роли → интеграции → открытые вопросы
- Минимум hardcode-решений — параметры настраиваются через панель администратора
