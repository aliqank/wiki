# Рабочие правила

## Язык и стиль
- Общение с пользователем — на **русском языке**.
- Технические и доменные термины из BRD сохранять как есть: `Fleet Owner`, `Service Work Request`, `Justification`, `Usage Rate`, `On-demand BP (Showcase)` и т.д.
- Ответы краткие и структурированные; таблицы и блоки кода использовать там, где это повышает читаемость.

## Последовательность работы с материалами
- Сначала открывать `Список материалов.md` в корне проекта.
- По описанию определять нужные файлы и читать их точечно.
- Массово сканировать репозиторий только если в `Список материалов.md` не хватает информации.
- При добавлении новых содержательных файлов обновлять `Список материалов.md`.

## Рабочий процесс по артефактам
- Самые черновые заметки и промежуточные рабочие материалы ведутся в `Документация в процессе работы с требованиями/` внутри папок месяцев и дней.
- После совместной аналитической проработки итоговый оформленный результат создаётся в **`.md` формате** в папке `Результаты claude/`.
- В `wiki/` ничего не переносить и не публиковать без прямой команды пользователя.
- `wiki/` предназначена только для финальных, согласованных, **ready-for-development** артефактов.

## Сохранение результатов в `Результаты claude/`
- Все оформленные аналитические результаты сохранять в папке `Результаты claude/` в формате `.md`.
- Имя файла: `YYYY-MM-DD - <краткое название темы>.md`.
- В начале каждого нового аналитического документа указывать:
  - **Дата создания:** `YYYY-MM-DD HH:MM`
  - **Последнее обновление:** `YYYY-MM-DD HH:MM`
  - **Автор:** `Тельман Нуржанов (SA)`
- Перед созданием файлов других форматов (`.bpmn`, `.xml`, код, экспортные файлы и т.п.) спрашивать пользователя.

## Работа с требованиями
- При анализе требований учитывать как финальные артефакты, так и AS-IS контекст из транскрипций и рабочих заметок.
- Явно фиксировать открытые вопросы, допущения и `TBD`-пункты.
- Предпочтительная структура аналитических документов: `контекст → AS-IS → TO-BE → сущности → роли → интеграции → открытые вопросы`.
- Избегать hardcode-решений: бизнес-параметры, таймауты, лимиты и справочники должны по возможности конфигурироваться через Admin Panel.

## Работа с `wiki/`
- `wiki/` не является рабочей зоной для черновиков.
- Перед переносом в `wiki/` должен существовать подготовленный артефакт в `Результаты claude/` или другой явно согласованный финальный источник.
- Любое обновление `wiki/` выполняется только по отдельной явной команде пользователя.
