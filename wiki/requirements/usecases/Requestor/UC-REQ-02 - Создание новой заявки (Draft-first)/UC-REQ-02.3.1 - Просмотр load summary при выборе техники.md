# UC-REQ-02.3.1 - Просмотр load summary при выборе техники

**Created:** 2026-05-28  
**Last updated:** 2026-06-02  
**Автор документов:** OpenCode

---

## Карточка use case

| Поле | Значение |
|---|---|
| Область действия | Окно `Добавить технику` |
| Участник | `Requestor`, `ServiceWorkProcessor` |
| Покрываемые FR (BRD) | `FR-NEW-70` |
| Покрываемые FR (Additional list) | — |
| Предусловие | Пользователь авторизован; выбрана техника; задан диапазон дат бронирования |
| Триггер | Выбор техники и указание периода бронирования в окне `Добавить технику` |
| Ожидаемый результат | Пользователь видит load summary по выбранной технике за указанный период, включая `Work Order number` для пересекающихся броней |
| Используемые API | [`GET /equipment/{id}/load-summary`](../../../../api/booking/requestor/GET_equipment_id_load_summary.md) |

---

## Основной сценарий

1. Пользователь открывает окно `Добавить технику` и находит подходящую технику.
2. Пользователь выбирает технику и задает даты планируемой брони.
3. Frontend определяет `equipmentId`, `plannedStartDateTime` и `plannedEndDateTime`.
4. Frontend вызывает [`GET /equipment/{id}/load-summary`](../../../../api/booking/requestor/GET_equipment_id_load_summary.md).
5. Backend проверяет существование техники и валидность выбранного периода.
6. Backend находит пересекающиеся активные брони по выбранной технике.
7. Backend возвращает load summary, включая:
   - `activeBookingsCount`;
   - список пересекающихся броней;
   - `workOrderNumber` для каждой пересекающейся брони.
8. Frontend отображает load summary в окне выбора техники.
9. Пользователь использует load summary для оценки конфликтов перед добавлением техники в заявку.

---

## Альтернативные сценарии

1. Для выбранной техники нет пересекающихся активных броней.
   Backend возвращает `activeBookingsCount = 0` и пустой список `items`; frontend показывает пустое состояние блока load summary.

2. Пользователь еще не указал полный диапазон дат.
   Frontend не вызывает load summary до ввода обязательных параметров периода.

3. Техника не найдена.
   Backend возвращает `NOT_FOUND`; frontend показывает сообщение об ошибке.

---

## Замечания

1. Load summary является информационным блоком и не блокирует выбор техники автоматически.
2. `Work Order number` помогает Requestor понять контекст пересекающихся броней до отправки заявки.
3. Данный use case является вспомогательным по отношению к `UC-REQ-02.3`.
