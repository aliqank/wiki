# UC-REQ-02.4 - Добавление техники в draft-заявку

**Created:** 2026-05-15  
**Last updated:** 2026-05-15  
**Автор документов:** Telman Nurzhanov (SA)

---

## Карточка use case

| Поле | Значение |
|---|---|
| Область действия | Окно `Добавить технику` |
| Участник | `Requestor`, `ServiceWorkProcessor` |
| Покрываемые FR (BRD) | `FR-031`, `FR-038`, `FR-NEW-04`, `FR-NEW-08`, `FR-NEW-15`, `FR-NEW-71` |
| Покрываемые FR (Additional list) | — |
| Триггер | Пользователь выбрал одну или несколько единиц техники и нажал `Добавить к заявке` |
| Ожидаемый результат | В draft-заявку добавлены booking item-ы |
| Используемые API | `POST /booking-requests/{id}/items` |

---

## Основной сценарий

1. Пользователь выбирает одну или несколько единиц техники в результатах поиска и нажимает `Добавить к заявке`.
2. Frontend вызывает `POST /booking-requests/{id}/items` и передаёт список выбранных единиц техники в `items[]`.
3. Backend создаёт отдельный booking item для каждой выбранной единицы техники внутри draft-заявки.
4. На этапе `POST /booking-requests/{id}/items` поле `justification` не передаётся.
5. Если для конкретного item требуется `justification`, этот item помечается как незавершённый до его заполнения позже, на основной странице заявки.
6. Backend возвращает список booking item-ов, созданных в текущем добавлении.
7. После выполнения `POST /booking-requests/{id}/items` frontend отображает пользователю страницу `Новая заявка / Редактировать заявку` с номером заявки.
8. В sidebar страницы сохраняются и отображаются request-level поля:
   - номер Work Order;
   - приоритет;
   - локация;
   - описание работ;
   - комментарий.
9. В центральной части страницы frontend отображает обновлённое состояние заявки с уже добавленными бронями.
10. В центральной части должен отображаться:
   - общее количество добавленной техники / броней по всей заявке, а не только по последнему вызову API;
   - список всех броней, уже входящих в заявку.
11. Для каждой брони в списке должны отображаться поля:
   - фото техники;
   - тип техники;
   - марка, модель;
   - номер ТШО;
   - ГРНЗ;
   - данные Fleet Owner;
   - плановые даты начала и завершения брони;
   - характеристики техники в виде `ключ - значение`;
   - поле `justification`, которое пользователь заполняет непосредственно в карточке / строке этой брони.
12. Таким образом, после добавления техники пользователь видит не отдельный результат последнего запроса, а обновлённое состояние страницы `Новая заявка` с полным составом брони по заявке.

---

## Альтернативные сценарии

1. Добавление item не прошло из-за недоступности техники.
   Backend возвращает ошибку валидации доступности; добавление выполняется как единое действие для переданного списка.

2. Добавлены несколько item-ов.
   Каждый item создаётся как самостоятельная запись, но все они передаются одним batch-запросом.

3. После добавления техники пользователь возвращается к редактированию заявки.
   Frontend показывает обновлённую страницу `Новая заявка / Редактировать заявку`, где отображается полный список всех броней заявки и общее количество добавленной техники.
