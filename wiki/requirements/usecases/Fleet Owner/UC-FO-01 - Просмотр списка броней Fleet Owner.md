# UC-FO-01 - Просмотр списка броней Fleet Owner

**Last updated:** 2026-05-19  
**Автор документов:** Telman Nurzhanov (SA)

---

## Карточка use case

| Поле | Значение |
|---|---|
| Область действия | Страница Fleet Owner `Approvals` → view `Bookings` |
| Участник | Пользователь с ролью `FleetOwner` |
| Покрываемые FR (BRD) | `FR-092`, `FR-043` |
| Покрываемые FR (Additional list) | — |
| Предусловие | Пользователь авторизован в системе; пользователь имеет роль `FleetOwner`; пользователю доступны один или несколько fleet-ов и/или права на делегированную технику |
| Триггер | Вход на страницу Fleet Owner `Approvals` c активной view `Bookings` |
| Ожидаемый результат | Отображается paginated список броней, относящихся к зоне ответственности Fleet Owner, с фильтрами и кратким request-level контекстом |
| Используемые API | `GET /approvals/bookings`, `GET /approvals/bookings/{id}` |

---

## Основной сценарий

1. Пользователь открывает страницу Fleet Owner `Approvals` и находится во view `Bookings`.
2. Frontend вызывает `GET /approvals/bookings`.
3. Backend определяет список fleet-ов, где у текущего Fleet Owner есть assignment в `FleetManagePermissions` с типом `Owner` или `Delegated`, а также технику, права по которой делегированы ему.
4. Backend возвращает paginated список booking-ов, относящихся только к этим fleet-ам или к технике, доступной пользователю по делегированию.
5. Frontend отображает таблицу броней.
6. Для каждой строки отображаются поля списка:
   - номер заявки;
   - requestor;
   - номер Work Order;
   - приоритет;
   - дата создания брони;
   - подвижность техники (`mobilityType`);
   - тип техники;
   - марка / модель;
   - номер ТШО;
   - ГРНЗ;
   - плановые даты брони;
   - статус брони;
   - таймер с момента submit.
7. Таймер отображает время нахождения конкретной брони в очереди Fleet Owner начиная с момента submit.
8. Пользователь может открыть detail / action flow по конкретной брони.
9. Frontend вызывает `GET /approvals/bookings/{id}` для выбранной строки.

---

## Альтернативные сценарии

1. У Fleet Owner нет доступных броней.
   Система отображает пустое состояние без строк таблицы.

2. Пользователь применяет фильтры.
   Frontend повторно вызывает `GET /approvals/bookings` с query-параметрами фильтрации.

3. Пользователь использует поиск по Work Order.
   Frontend передает строку поиска; backend выполняет поиск по `workOrderNumber`.

4. Пользователь переключает статусный фильтр.
   Frontend обновляет список согласно набору статусов, допустимых для view `Bookings`.

5. Backend возвращает ошибку авторизации или доступа.
   Frontend отображает сообщение об ошибке и не показывает данные таблицы.

---

## Замечания

1. View `Bookings` является booking-centric: одна строка списка соответствует одной броне.
2. В список не должны попадать чужие брони, не относящиеся к fleet-ам Fleet Owner и не связанные с техникой, доступной ему по делегированию.
3. Набор статусов в фильтре для view `Bookings` является самостоятельным и может отличаться от набора статусов в агрегированной view `Requests`.
4. Таймер должен считаться от момента submit, а не от момента создания заявки или брони.
5. Массовые действия в рамках текущей версии use case не предполагаются.
