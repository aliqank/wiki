# UC-FO-02.1 - Просмотр load summary Fleet Owner

## Карточка use case

| Поле | Значение |
|---|---|
| Область действия | Страница Fleet Owner `Approvals` -> detail / action view конкретной брони |
| Участник | Пользователь с ролью `FleetOwner` |
| Покрываемые FR (BRD) | `FR-NEW-64` |
| Покрываемые FR (Additional list) | — |
| Предусловие | Пользователь авторизован в системе; пользователь имеет роль `FleetOwner`; бронь относится к зоне ответственности пользователя; открыта карточка брони в approval window |
| Триггер | Открытие блока `Load summary` в карточке брони или переход в detail / action view брони |
| Ожидаемый результат | Пользователь видит сводку пересекающихся активных броней по той же технике на даты текущей брони |
| Используемые API | `GET /approvals/bookings/{id}/load-summary` |

---

## Основной сценарий

1. Fleet Owner открывает detail / action view конкретной брони из очереди `Approvals`.
2. Frontend определяет `bookingId` выбранной брони.
3. Frontend вызывает `GET /approvals/bookings/{id}/load-summary`.
4. Backend проверяет, что:
   - бронь существует;
   - текущий пользователь имеет доступ к брони как Fleet Owner;
   - бронь относится к зоне ответственности пользователя.
5. Backend находит пересекающиеся активные брони по тому же `equipmentId` на даты текущей брони.
6. Backend исключает из результата текущую бронь.
7. Backend возвращает summary для approval window:
   - `equipmentId`;
   - `activeBookingsCount`;
   - список пересекающихся броней.
8. Frontend отображает load summary в карточке брони.
9. Пользователь использует load summary как входные данные для дальнейшего решения по брони.

---

## Альтернативные сценарии

1. Для выбранной техники нет пересекающихся активных броней.
   Backend возвращает `activeBookingsCount = 0` и пустой список `items`; frontend показывает пустое состояние блока load summary.

2. Пользователь не имеет доступа к брони.
   Backend возвращает `FORBIDDEN`; frontend не показывает данные load summary и отображает сообщение об ошибке.

3. Бронь не найдена.
   Backend возвращает `NOT_FOUND`; frontend показывает сообщение об ошибке.

---

## Замечания

1. Load summary используется как информационный блок для принятия решения Fleet Owner и сам по себе не является hard-stop механизмом.
2. В summary должны попадать только пересекающиеся активные брони по той же технике, а не вся история бронирований.
3. Данный use case является вспомогательным по отношению к `UC-FO-02` и может вызываться до confirm / decline решения.
