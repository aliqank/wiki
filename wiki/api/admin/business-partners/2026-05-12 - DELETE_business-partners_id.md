## 1. Задачи, в рамках которых вносятся изменения в метод

Новый метод. Обрабатывает удаление записи бизнес-партнёра из справочника Admin Panel. Удаление реализовано как soft delete. Если бизнес-партнёр используется хотя бы одним активным external user, удаление запрещено.

## 3. Описание логики работы метода

1. Найти запись в `BusinessPartners` WHERE `id` = `:id` AND `isDeleted = false`. Если запись не найдена — вернуть `404 NOT_FOUND`.
2. Проверить наличие активных external users: COUNT(`Users` WHERE `businessPartnerId` = `:id` AND `type` = `external` AND `isDeleted = false`). Если count > 0 — вернуть `409 BUSINESS_PARTNER_IN_USE` с деталями (`externalUsersCount`).
3. Выполнить soft delete: обновить запись `BusinessPartners` — установить `isDeleted = true`, `deletedAt` = текущее время, `deletedBy` = ID аутентифицированного пользователя.
4. Вернуть HTTP 204 No Content (без тела ответа).

Сущности, участвующие в методе:
- читаются: `BusinessPartners`, `Users`
- изменяются: `BusinessPartners` (soft delete: UPDATE `isDeleted`, `deletedAt`, `deletedBy`)
- транзакционность: не требуется

## 9. Возвращаемые данные

При успешном выполнении метод возвращает **HTTP 204 No Content** без тела ответа.

При возникновении ошибки (`409 BUSINESS_PARTNER_IN_USE`) возвращается стандартный `result wrapper` с заполненным массивом `errors`.

## Замечания

1. Guard на уровне API обязателен, даже если frontend заблаговременно блокирует кнопку удаления по `externalUsersCount`.
2. После успешного soft delete запись перестаёт возвращаться в `GET /business-partners` и недоступна для привязки к новым external users.
