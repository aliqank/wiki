# 9524558 FR-009 Admin can delete existing fleets (soft deletion)

**Created:** 2026-06-03  
**Tester:** Artur Mukhitov  
**BRD:** v13  
**DB Schema:** v12  

---

## TC-001 — Успешное soft-удаление флота (Happy Path)

**Precondition:** Admin авторизован. Флот существует, активен (`isDeleted = 0`), без техники и активных бронирований.

**Steps:**
1. Открыть Admin Panel → раздел флотов
2. Выбрать флот → нажать "Удалить"
3. Подтвердить удаление

**Expected:**
- Ответ 200/204
- В БД: `Fleets.isDeleted = 1`, `deletedAt` = текущий datetime (UTC), `deletedBy` = userId Admin
- Флот **не отображается** в активном списке флотов
- Флот **не возвращается** в `GET /reference/fleets`

**Result:** ✅ PASS (ретест)

---

## TC-002 — Удалённый флот не отображается в списках

**Precondition:** Флот был soft-удалён (TC-001 пройден).

**Steps:**
1. Запросить список флотов в Admin Panel
2. Запросить `GET /api/booking/v1/reference/fleets`

**Expected:**
- Удалённый флот отсутствует в обоих списках

**Result:** ✅ PASS с замечанием — флот отсутствует в Admin Panel ✅ и в `GET api/v1/fleet?PageIndex=1&PageSize=10` ✅. **Дефект:** endpoint в требованиях (`GET /api/booking/v1/reference/fleets`) не существует — фактический endpoint `GET api/v1/fleet`.

**Result:** 🚫 BLOCKED (ретест) — заблокирован дефектом US 9524546 TC-002: уникальность имён не проверяется в принципе

## TC-004 — Удаление несуществующего флота (Negative)

1. Отправить запрос удаления с несуществующим `fleetId` (случайный UUID)

- `isSuccess: false`, ошибка `FLEET_NOT_FOUND`

**Result:** ❌ FAIL — HTTP 200 success вместо 404; сервер не проверяет существование флота перед удалением

## TC-005 — Повторное удаление уже удалённого флота (Negative)

**Precondition:** Флот уже soft-удалён (`isDeleted = 1`).

**Steps:**
1. Повторно отправить запрос удаления того же флота

**Expected:**
- HTTP 404 (или 409)
- Система не выполняет повторное удаление
- `deletedAt` и `deletedBy` не перезаписываются

**Result:** ❌ FAIL — HTTP 200 success вместо 404/409; повторное удаление не отклоняется

## TC-006 — Удаление флота с активной техникой (Guard)

**Precondition:** Флот содержит технику (`isDeleted = 0` в таблице `Equipments`).

**Steps:**
1. Попытаться удалить флот, в котором есть активная техника

**Expected:**
- ⚠️ Поведение требует уточнения у SA/разработчика
- Вариант A: HTTP 409 — `FLEET_HAS_ACTIVE_EQUIPMENT`, удаление запрещено
- Вариант B: каскадное soft-удаление техники вместе с флотом

**Result:** ❌ FAIL — флот с активной техникой удалён без ошибки, guard-проверка отсутствует. Поведение не соответствует ожидаемому (требует уточнения: является ли это дефектом или допустимым каскадом)

## TC-007 — Удаление флота с активными бронированиями (Guard)

**Precondition:** Техника флота имеет активные брони (статус `Submitted` / `Confirmed` / `InProgress`).

**Steps:**
1. Попытаться удалить флот, у которого есть техника с активными бронями

**Expected:**
- ⚠️ Поведение требует уточнения у SA/разработчика
- Наиболее ожидаемо: HTTP 409 — удаление запрещено до закрытия активных броней

**Result:** 🚫 BLOCKED — невозможно создать бронирование для подготовки precondition теста. ⚠️ По аналогии с TC-006 (guard отсутствует) — высокая вероятность FAIL; проверить отдельно при наличии активных броней

## Заметки

- API-спецификация Admin fleet delete в `wiki/api/admin/` отсутствует — уточнить endpoint у разработчиков
- TC-006 и TC-007 — поведение при наличии связанных данных не описано в BRD; требует уточнения у SA перед прогоном
- TC-003 связан с дефектом из US 9524546 TC-002 (уникальность не проверяется); при фиксе того дефекта перепроверить этот TC
- TC-010: уточнить, обновляются ли `updatedAt`/`updatedBy` при soft-delete (зависит от реализации)
- **Дефект (TC-004 + TC-005):** DELETE fleet endpoint возвращает HTTP 200 при удалении несуществующего флота и при повторном удалении уже удалённого флота — отсутствует проверка существования и состояния `isDeleted`
