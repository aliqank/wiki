## Принятые решения

### По реестру требований (09.04 встреча):
- Закрытие заявки — **только по кнопке**, автозакрытие по времени не применяется (R-75)
- Старт мобилизации фиксируется кнопкой «Мобилизация началась» на стороне FO (R-72)
- Трёхшаговый флоу Unwheeled: Requestor → FO добавляет ТС → роль «Транспортировка» подтверждает → FO финально утверждает (R-20 обновлён)
- Одна форма → система автоматически разбивает на атомарные заявки, связь через Work Order (R-19)
- Нет обязательного буфера между бронями (R-02 закрыт)
- Отдельная роль «Ответственный за транспортировку» — Heavy Ops (Ерлан) + команда Азбека (R-74)
- При закрытии Requestor вводит фактическое время начала и окончания работ (R-71)
- Приоритет внутренней техники — бизнес-правило, не технически принудительно

### По gap-анализу — выявлены критические пробелы реестра:
- **Уведомления** (BRD FR-076..090) — 15 требований, нулевое покрытие в реестре
- **Admin Panel** (BRD FR-005..016) — 12 требований, практически нет
- **Service Work Processor + SWR флоу** — весь блок отсутствует
- **Статусная машина Booking** (14 переходов BRD FR-062..075) — только агрегированный статус
- **Revoke / Terminate / Extend** (FR-058..061) — не зафиксированы в реестре
- **Отчётность** (FR-091..097) — только аудит R-10
- **PSWS / DOA / DataLake** — интеграции полностью отсутствуют
- **Конфликт:** BRD предполагает автопереходы статуса Booking по datetime (FR-070/071), реестр принял решение «только по кнопке» (R-75) — нужно задокументировать как явное отклонение от BRD
