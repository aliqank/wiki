## Принятые решения

### GIS-карта
- Скорость и направление движения — отображать для JSM-трекеров (питаются от транспорта, real-time)
- Eor One (батарейка, 3 раза/день) — направление не отображается (данные слишком редкие)
- Топливо — **Phase 1 НЕ отображать** (телематика не будет поступать)
- Исторический маршрут — отображать (желательно), горизонт 7 дней
- При клике на технику — отображать все данные с датчиков (по последней синхронизации); корректировать по фидбэку бизнеса
- GIS-карта целиком на стороне команды **атлас/Hayr** (iframe). Booking Tool только передаёт требования.
- Нужен отдельный созвон с командой GIS

### Дашборд утилизации
- Новое требование **D-NEW-1**: добавить количество бронирований за период рядом со средней утилизацией
- Градиентная закраска: % от плана (не фиксированные пороги), план задаётся для каждой единицы
- 3 таба (моточасы / километраж / комбайн) — подтверждено
- Круговые диаграммы и пироги не нужны — только цифры/факты

### Заявки FO
- Новое требование **D-NEW-2**: добавить в окно согласования FO сводку загруженности техники по датам (аналог билетного окошка — видны другие активные брони)

### Карточка оборудования
- Единая база данных для TCO и BP-техники (подтверждено)
- Для BP (long-term rented) ряд полей **необязателен**: ТШО-номер, госномер, ВИН, серийный номер, год выпуска
- Компания по ремонту — **желательно хранить** (у одной техники могут быть разные подрядчики по видам работ)
- Операционный статус — убирается; остаются статус ремонта и статус заморозки
- Пожарные машины (Assigned) — возможно, исключить из фильтрации для Requestor (TBD)

### Организационное
- Новый участник проекта: **Валерий** — аналитик по мониторингу
- Технические интеграции (API, DataLake и т.д.) — отдельные технические сессии с Аяном
