- Задача: подготовить аргументированный документ для бизнеса — почему модель «1 заявка = несколько FO, разные даты/локации» является проблематичной
- Создали полный аналитический документ с Mermaid-диаграммами, ASCII-wireframes и альтернативными предложениями

## Принятые решения

- **Рекомендованная модель (Вариант B):** 1 заявка = 1 FO (или N единиц от 1 FO), группировка по WO в интерфейсе
  - Пользователь видит контекст через Work Order Number
  - Каждая заявка имеет чёткий статус, один SLA, один поток согласования
  - Система автоматически разбивает по FO при создании
- Вариант C (что просит бизнес) технически реализуем, но создаёт 6 операционных проблем
