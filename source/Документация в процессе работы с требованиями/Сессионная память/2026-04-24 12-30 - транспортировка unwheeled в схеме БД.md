## Принятые решения

### Транспортировка unwheeled-техники (OQ-DB-9 → CLOSED)
- **Архитектура:** отдельная таблица `TransportRequests` не нужна — расширяем таблицу `Bookings`
- **Поле:** `transportBookingId UUID nullable FK → Bookings` (self-referencing FK) — у unwheeled-брони хранится ссылка на бронь транспортной техники
- **Направление FK:** unwheeled → грузовик (не наоборот), потому что один грузовик может везти несколько unwheeled, но обратного не бывает
- **Новый статус:** `TransportConfirmed` в `Bookings.status` — вставляется между `Confirmed` и `InProgress`, только для unwheeled-броней
- **Жизненный цикл unwheeled:** `Draft → Submitted → Confirmed → TransportConfirmed → InProgress → Closed`
- **Транспортный откат:** если транспортная бронь отменяется (Declined/Terminated/Revoked) — unwheeled возвращается в `Confirmed`, `transportBookingId` обнуляется; обрабатывается на уровне приложения, не каскадом FK
- **FK-исключение:** `transportBookingId` — единственное поле в Booking-блоке с реальным FK-ограничением (self-ref внутри таблицы); остальные внешние ID — без FK-ограничений

### previousSnapshot расширен
- При переходе в `TransportConfirmed`: `{"transportBookingId": null}` — фиксирует первичную привязку
- При откате в `Confirmed` (когда транспорт сорвался): `{"transportBookingId": "..."}` — фиксирует обнулённый ID
