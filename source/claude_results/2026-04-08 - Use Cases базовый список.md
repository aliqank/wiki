# Use Cases — Базовый список
**Дата:** 2026-04-08
**Тип документа:** Use Case Registry v1
**Scope:** Phase 1 · Внутренний флот (Cat 1) · Роли: Requestor, Fleet Owner, Admin
**Исключено:** Внешние бизнес-партнёры (Cat 3), Contract Specialist, CC Owner, DCT/RWA

---

## Акторы

| Актор | Описание |
|-------|----------|
| **Requestor** | Сотрудник TCO, подающий заявку на технику |
| **Fleet Owner (FO)** | Руководитель/ответственный за парк техники; принимает или отклоняет заявки |
| **System** | Автоматические действия системы (таймеры, уведомления, проверки) |
| **Admin** | Системный администратор; настраивает параметры и управляет справочниками |
| **Azure AAD** | Внешняя система аутентификации (SSO) |

---

## UC-01 — Аутентификация
**Актор:** Requestor / FO / Admin · **Уровень:** Обязательный
**Описание:** Пользователь входит в систему через Azure SSO. Система определяет роль по AAD-группе.
**Основной сценарий:**
1. Пользователь открывает Booking Tool
2. Redirect на Azure AAD login page
3. Успешная аутентификация → система создаёт сессию, определяет роль (Requestor / FO / Admin)
4. Перенаправление на Dashboard

**Альтернативы:** Нет доступа в AAD-группе → отказ в доступе с сообщением

**Требования:** R-06 (авторизация), архитектурное решение Azure SSO

## БЛОК 1 — Requestor: Работа с заявкой

### UC-02 — Поиск и выбор техники
**Актор:** Requestor · **Уровень:** Обязательный
**Описание:** Requestor фильтрует каталог по типу, характеристикам и периоду; выбирает конкретную единицу у конкретного FO.
**Основной сценарий:**
1. Requestor переходит в «Каталог техники»
2. Задаёт фильтры: тип техники, период (дата/время from–to), технические характеристики
3. Система возвращает список доступных единиц (Shared + SWC; Assigned — скрыты)
4. Requestor просматривает карточки: модель, FO, характеристики, share-статус, подвижная/стационарная
5. Requestor выбирает конкретную единицу → переход к UC-03

**Альтернативы:**
- A1: Нет доступной техники → пустое состояние с предложением изменить параметры
- A2: Техника стационарная → система показывает предупреждение о трале (R-43)

**Требования:** R-55, R-61, R-12, R-13, R-14, R-02, R-43

---

### UC-03 — Создание заявки
**Актор:** Requestor · **Уровень:** Обязательный
**Описание:** Requestor создаёт заявку на выбранную единицу техники.
**Основной сценарий:**
1. Форма предзаполнена выбранной техникой и периодом из UC-02
2. Requestor заполняет обязательные поля: GDE/JDE Work Order №, Приоритет (P1–P4)
3. Опционально: Описание работ
4. Requestor нажимает «Подать заявку»
5. Система повторно проверяет доступность техники в указанный период
6. Система создаёт Request со статусом Pending FO; уведомляет FO

**Альтернативы:**
- A1: Техника стала недоступна между выбором и подачей → ошибка, возврат в каталог
- A2: Work Order не заполнен → форма не даёт отправить

**Постусловие:** Request создан, FO уведомлён

**Требования:** R-01, R-15, R-16, R-28, R-62, R-02

---

### UC-04 — Просмотр списка своих заявок
**Актор:** Requestor · **Уровень:** Обязательный
**Описание:** Requestor просматривает все свои заявки с фильтрацией по статусу, приоритету, дате.
**Основной сценарий:**
1. Requestor переходит на «Мои заявки»
2. Видит список заявок с колонками: тип техники, FO, период, приоритет, статус, дата создания
3. Применяет фильтры при необходимости
4. Кликает на строку → UC-05

**Требования:** R-10

---

### UC-05 — Просмотр деталей заявки (Requestor)
**Актор:** Requestor · **Уровень:** Обязательный
**Описание:** Просмотр полной информации по заявке: статус, назначенная техника, таймлайн событий.
**Основной сценарий:**
1. Requestor открывает заявку из списка
2. Видит: шапку (№, статус, приоритет), блок техники, параметры (WO, описание), таймлайн событий
3. Видит контекстные кнопки действий по текущему статусу

**Контекстные действия по статусу:**
- Pending / Draft → UC-06 (редактировать), UC-07 (отозвать)
- Action Required (FO отказал) → UC-02 (выбрать другую технику)
- Confirmed / In Progress → UC-11 (завершить), UC-12 (запросить продление)

**Требования:** R-10

---

### UC-06 — Редактирование заявки
**Актор:** Requestor · **Уровень:** Важный
**Предусловие:** Request в статусе Draft или Pending FO
**Описание:** Requestor изменяет параметры заявки (WO, приоритет, описание, технику).
**Основной сценарий:**
1. Requestor нажимает «Редактировать» в деталях заявки
2. Изменяет поля (или через «Изменить технику» возвращается в каталог)
3. Сохраняет → система обновляет заявку и повторно уведомляет FO если статус Pending

**Ограничения:** Редактирование недоступно при статусах Confirmed, In Progress, Completed, Rejected

**Требования:** R-01, R-28, R-62

---

### UC-07 — Отзыв заявки
**Актор:** Requestor · **Уровень:** Важный
**Предусловие:** Request в статусе Draft или Pending FO
**Описание:** Requestor отзывает (отменяет) заявку до подтверждения FO.
**Основной сценарий:**
1. Requestor нажимает «Отозвать заявку» → подтверждение
2. Статус Request → Cancelled
3. Если FO уже получил уведомление — FO уведомляется об отзыве

**Требования:** R-02 (техника освобождается)

---

### UC-08 — Выбор другой техники после отказа FO
**Актор:** Requestor · **Уровень:** Обязательный
**Предусловие:** Request в статусе Action Required (FO отказал)
**Описание:** Requestor видит причину отказа и выбирает другую единицу техники в той же заявке.
**Основной сценарий:**
1. Requestor получает уведомление об отказе (причина видна)
2. В деталях заявки → кнопка «Выбрать другую технику»
3. Переход в каталог UC-02 (период сохранён, тип сохранён)
4. Requestor выбирает другую единицу → заявка обновляется, уходит к новому FO

**Альтернативы:**
- Нет подходящей техники в каталоге → Requestor может закрыть заявку

**Требования:** R-56, R-55

---

### UC-09 — Запрос на продление бронирования
**Актор:** Requestor · **Уровень:** Важный
**Предусловие:** Booking в статусе Confirmed или In Progress
**Описание:** Requestor запрашивает продление времени бронирования.
**Основной сценарий:**
1. Requestor нажимает «Запросить продление» в деталях заявки
2. Указывает новую дату/время окончания, опциональный комментарий
3. Если у техники есть следующая бронь — система показывает предупреждение
4. Запрос уходит FO → UC-18 (FO отвечает)

**Требования:** R-58

---

### UC-10 — Завершение бронирования (Requestor)
**Актор:** Requestor · **Уровень:** Обязательный
**Предусловие:** Booking в статусе In Progress
**Описание:** Requestor отмечает, что работа завершена, техника может быть освобождена.
**Основной сценарий:**
1. Requestor нажимает «Завершить» в деталях заявки
2. Подтверждение в диалоге
3. Booking → Completed; техника → Available

**Требования:** R-57

## БЛОК 2 — Fleet Owner: Работа с заявками

### UC-11 — Просмотр входящих заявок
**Актор:** Fleet Owner · **Уровень:** Обязательный
**Описание:** FO видит все заявки, адресованные ему, с фильтрацией и индикацией срочности.
**Основной сценарий:**
1. FO переходит на «Входящие заявки»
2. Видит список: Requestor, тип техники, период, приоритет, таймер тайм-аута, статус
3. P1-заявки с истекающим таймером выделены визуально
4. FO кликает на заявку → UC-12

**Требования:** R-23, R-24

---

### UC-12 — Просмотр деталей заявки (FO)
**Актор:** Fleet Owner · **Уровень:** Обязательный
**Описание:** FO видит полные данные заявки перед принятием решения.
**Основной сценарий:**
1. FO открывает заявку
2. Видит: Requestor, Work Order, описание, запрошенную технику из своего парка, период, приоритет
3. Видит доступность техники в запрошенный период
4. Контекстные кнопки: «Принять», «Отклонить»

**Требования:** R-23, R-33

---

### UC-13 — Принятие заявки
**Актор:** Fleet Owner · **Уровень:** Обязательный
**Предусловие:** Request в статусе Pending FO
**Описание:** FO подтверждает бронирование запрошенной техники.
**Основной сценарий:**
1. FO нажимает «Принять заявку»
2. Система: Request → Confirmed; Booking создаётся; техника → Booked на период
3. Requestor уведомляется о подтверждении

**Альтернативы:**
- Техника уже занята (конфликт) → система предупреждает, предлагает выбрать другую (UC-14b)

**Требования:** R-02, R-27

---

### UC-14 — Отклонение заявки
**Актор:** Fleet Owner · **Уровень:** Обязательный
**Предусловие:** Request в статусе Pending FO
**Описание:** FO отклоняет заявку с обязательным указанием причины.
**Основной сценарий:**
1. FO нажимает «Отклонить»
2. Модальное окно с обязательным полем «Причина» (quickpick или ввод)
3. FO подтверждает
4. Request → Action Required; причина сохранена; Requestor уведомлён с причиной

**Требования:** R-33, R-56

---

### UC-15 — Замена техники в подтверждённой заявке
**Актор:** Fleet Owner · **Уровень:** Важный
**Предусловие:** Booking Confirmed или In Progress
**Описание:** FO назначает другую единицу из своего парка (например, назначенная вышла из строя).
**Основной сценарий:**
1. FO нажимает «Изменить технику» в деталях заявки
2. Список доступных единиц из своего парка того же типа на тот же период
3. FO выбирает замену
4. Booking обновляется; Requestor уведомляется

**Требования:** R-27

---

### UC-16 — Назначение транспорта (трал) для стационарной техники
**Актор:** Fleet Owner · **Уровень:** Важный
**Предусловие:** В заявке есть стационарная техника
**Описание:** FO вручную назначает вид и кол-во транспорта для доставки стационарной техники.
**Основной сценарий:**
1. В деталях заявки FO видит блок «Транспорт — не назначен»
2. Нажимает «Назначить транспорт»
3. Выбирает тип (трал / бумтрак / грузовик) и кол-во
4. Сохраняет

**Требования:** R-60, R-43

---

### UC-17 — Завершение бронирования (FO)
**Актор:** Fleet Owner · **Уровень:** Обязательный
**Предусловие:** Booking In Progress
**Описание:** FO отмечает, что техника вернулась и работа завершена.
**Основной сценарий:**
1. FO нажимает «Завершить»
2. Подтверждение
3. Booking → Completed; техника → Available; Requestor уведомляется

**Требования:** R-57

---

### UC-18 — Ответ на запрос продления
**Актор:** Fleet Owner · **Уровень:** Важный
**Предусловие:** Requestor подал UC-09
**Описание:** FO одобряет или отклоняет запрос на продление бронирования.
**Основной сценарий:**
1. FO видит баннер «Запрос на продление» в деталях заявки
2. Видит новую предложенную дату + следующую бронь (если есть)
3. Выбирает «Одобрить» или «Отклонить»
4. При одобрении: Booking обновляется; Requestor уведомляется
5. При отказе: Requestor уведомляется с комментарием

**Требования:** R-58

## БЛОК 3 — Fleet Owner: Управление парком

### UC-19 — Просмотр своего парка
**Актор:** Fleet Owner · **Уровень:** Обязательный
**Описание:** FO просматривает все единицы техники своего флота с текущими статусами.
**Основной сценарий:**
1. FO переходит на «Мой парк»
2. Видит таблицу: тип, модель, S/N, характеристики, share-статус, текущий статус, активные брони
3. Фильтрация по типу, статусу, движимости

**Требования:** R-12, R-14, R-61

---

### UC-20 — Добавление техники в парк
**Актор:** Fleet Owner · **Уровень:** Обязательный
**Описание:** FO добавляет новую единицу техники в свой парк.
**Основной сценарий:**
1. FO нажимает «Добавить технику»
2. Заполняет форму: тип, производитель, модель, S/N, госномер (опц.), движимость, характеристики по типу, share-тип, категория (Cat 1/Cat 2)
3. Сохраняет → техника появляется в каталоге (если Shared/SWC)

**Требования:** R-12, R-31, R-61

---

### UC-21 — Редактирование карточки техники
**Актор:** Fleet Owner · **Уровень:** Важный
**Описание:** FO обновляет параметры единицы техники (характеристики, share-тип).
**Предусловие:** Нет активного бронирования на эту единицу (или система предупреждает об активных бронях)

**Требования:** R-12, R-05

---

### UC-22 — Удаление техники из парка
**Актор:** Fleet Owner · **Уровень:** Средний
**Описание:** FO удаляет единицу из активного парка (вывод из эксплуатации).
**Предусловие:** Нет активных броней на эту единицу
**Ограничения:** Исторические данные о бронированиях сохраняются (R-10)

---

### UC-23 — Заморозка техники (ТО / КАП-ремонт)
**Актор:** Fleet Owner · **Уровень:** Важный
**Описание:** FO временно выводит технику из доступности (техническое обслуживание, ремонт).
**Основной сценарий:**
1. FO выбирает единицу в своём парке → «Заморозить»
2. Указывает период (от–до) или бессрочно
3. Техника → статус Frozen; исчезает из каталога; pending-заявки уведомляются

**Требования:** R-05

---

### UC-24 — Разморозка техники
**Актор:** Fleet Owner · **Уровень:** Важный
**Описание:** FO возвращает замороженную технику в доступность.

**Требования:** R-05

## БЛОК 4 — Системные Use Cases

### UC-25 — Проверка доступности техники
**Актор:** System · **Уровень:** Обязательный
**Описание:** Перед созданием/подтверждением бронирования система проверяет отсутствие конфликтов по периоду.
**Триггер:** UC-03 (создание), UC-13 (подтверждение), UC-02 (поиск)

**Требования:** R-02

---

### UC-26 — Отправка уведомлений
**Актор:** System · **Уровень:** Обязательный
**Описание:** Система отправляет уведомления при изменении статусов заявки и по таймерам.

| Событие | Кому |
|---------|------|
| Заявка создана | FO |
| Заявка подтверждена | Requestor |
| Заявка отклонена (с причиной) | Requestor |
| Тайм-аут FO приближается | FO (reminder) |
| Запрос на продление | FO |
| Продление одобрено/отклонено | Requestor |
| Бронирование завершено | Requestor + FO |
| Техника заменена FO | Requestor |

**Требования:** R-24

---

### UC-27 — Тайм-аут ответа FO (эскалация)
**Актор:** System · **Уровень:** Обязательный
**Описание:** Если FO не ответил в настраиваемый тайм-аут — система отправляет reminder; при истечении — возвращает заявку Requestor-у (статус Action Required).
**Триггер:** Таймер с момента получения заявки FO

**Требования:** R-23, R-24, R-56, R-29
