## Назначение документа

Этот шаблон предназначен для единообразного описания API-методов в проекте TCO HDV/HDE Booking Tool.

Шаблон подготовлен на основе:
- `Документация в процессе работы с требованиями/2026-05/2026-05-05/Пример описания API.pdf`
- `Документация в процессе работы с требованиями/2026-05/2026-05-05/Структура описания API.txt`
- `Документация в процессе работы с требованиями/2026-05/2026-05-05/API - Обертка результата (использовать во всех API).pdf`
- `Документация в процессе работы с требованиями/2026-05/2026-05-05/API - результат пагинации.pdf`

Использование:
- для каждого API-метода создаётся отдельный документ;
- структура разделов сохраняется без изменений;
- примеры запросов и ответов приводятся в JSON;
- возвращаемые данные должны учитывать общий result wrapper, если это требуется общими соглашениями проекта.

## 9. Возвращаемые данные

Возвращаемые данные должны описываться с учётом двух отдельных шаблонов:
- `Результаты claude/2026-05-05 - Шаблон обертки результата API.md` — для общего result wrapper, который используется во всех API;
- `Результаты claude/2026-05-05 - Шаблон результата пагинации API.md` — для paginated result, когда метод возвращает список с пагинацией.

Правило применения:
- если метод возвращает один объект или коллекцию без пагинации, в разделе 9 нужно ссылаться на шаблон обёртки результата;
- если метод возвращает коллекцию с пагинацией, в разделе 9 нужно ссылаться и на шаблон обёртки результата, и на шаблон результата пагинации.

### 9.1 Структура response payload

| № | Описание поля | Наименование поля модели | Тип параметра (backend) | Формат | Значение по умолчанию | Источник данных | Комментарий |
|---|----------------|---------------------------|--------------------------|--------|------------------------|-----------------|-------------|
| 1 | <Описание поля> | `<fieldName>` | `<string / uuid / int / bool / object / array<...>>` | <формат> | <default> | <таблица / сервис / вычисление> | <Комментарий> |

### 9.2 Пример ответа

```json
{
  "value": {
    "field": "value"
  },
  "isSuccess": true,
  "errors": []
}
```

### 9.3 Что обязательно указать в разделе

В каждом конкретном API-документе в разделе `9. Возвращаемые данные` нужно явно указать:
- используется ли общий result wrapper;
- используется ли `PaginatedResult`;
- что именно лежит в `value`;
- структуру элементов списка, если `value` содержит пагинированную коллекцию;
- пример полного JSON-ответа, а не только внутренней модели.

## Рекомендации по заполнению

1. Один файл = один API-метод.
2. Название файла лучше задавать в формате: `YYYY-MM-DD - API <краткое название>.md`.
3. Если API связан с конкретным экраном, полезно в начале документа указать экран / модалку / use case.
4. Если метод использует справочники, enum или системные настройки, это должно быть отражено явно, а не только в логике.
5. Для response желательно явно разделять:
   - что приходит напрямую из БД;
   - что вычисляется backend-логикой;
   - что является агрегатом из нескольких сущностей.
6. Для методов изменения данных желательно отдельно фиксировать guard-условия удаления / редактирования.
