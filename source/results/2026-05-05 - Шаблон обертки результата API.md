## Назначение

Этот шаблон описывает общий result wrapper, который должен использоваться во всех API-методах.

Источник:
- `Документация в процессе работы с требованиями/2026-05/2026-05-05/API - Обертка результата (использовать во всех API).pdf`

## Структура обертки результата

| № | Описание поля | Наименование поля модели | Тип параметра (backend) | Комментарий |
|---|----------------|---------------------------|--------------------------|-------------|
| 1 | Результат | `value` | `<T>` | Модель или коллекция моделей |
| 2 | Успешный | `isSuccess` | `bool` | Признак успешности выполнения метода |
| 3 | Ошибки | `errors` | `array` | Коллекция ошибок. При успешном результате выполнения метода должна быть пустой |
| 3.1 | Сообщение | `message` | `string` | Содержит информацию об ошибке, не переводится |
| 3.2 | Код | `code` | `string` | Код ошибки в таблице Localization |
| 3.3 | Поле | `property` | `string | null` | При ошибках валидации содержит наименование свойства, иначе `null` |
| 3.4 | Признаки | `tags` | `Dictionary<string, string>` | Словарь признаков и значений для подстановки |

## Рекомендуемый JSON-шаблон

### Успешный ответ

```json
{
  "value": {
    "field": "value"
  },
  "isSuccess": true,
  "errors": []
}
```

### Успешный ответ со списком

```json
{
  "value": [
    {
      "id": "uuid"
    }
  ],
  "isSuccess": true,
  "errors": []
}
```

### Ответ с ошибкой

```json
{
  "value": null,
  "isSuccess": false,
  "errors": [
    {
      "message": "Validation failed",
      "code": "VALIDATION_ERROR",
      "property": "name",
      "tags": {
        "maxLength": "255"
      }
    }
  ]
}
```

## Как ссылаться из API-документа

В разделе `9. Возвращаемые данные` конкретного API-документа рекомендуется писать так:

```md
Возвращаемые данные должны быть обёрнуты в общий result wrapper.
См. шаблон: `Результаты claude/2026-05-05 - Шаблон обертки результата API.md`.
```

Если метод возвращает пагинированный список, дополнительно нужно сослаться на шаблон пагинации.

---

## Примечания

1. `value` может содержать:
   - одиночную модель;
   - коллекцию моделей;
   - `PaginatedResult`;
   - `null` при ошибке.
2. `errors` всегда должен присутствовать в ответе, даже если он пустой.
3. Для методов валидации нужно заполнять `property`, если ошибка относится к конкретному полю.
4. `tags` использовать для параметров подстановки и дополнительного машинно-читаемого контекста ошибки.
