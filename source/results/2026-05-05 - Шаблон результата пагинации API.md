## Назначение

Этот шаблон описывает структуру `PaginatedResult`, которую нужно использовать для API-методов, возвращающих постраничный список.

Источник:
- `Документация в процессе работы с требованиями/2026-05/2026-05-05/API - результат пагинации.pdf`

---

## Структура результата пагинации

| № | Описание поля | Наименование поля модели | Тип параметра (backend) | Комментарий |
|---|----------------|---------------------------|--------------------------|-------------|
| 1 | Результат | `paginatedResult` | `object` | Результат пагинации |
| 1.1 | Элементы | `items` | `array<T>` | Список элементов текущей страницы |
| 1.2 | Всего | `total` | `int` | Общее количество элементов без учёта пагинации |

---

## Рекомендуемый JSON-шаблон самой пагинации

```json
{
  "items": [
    {
      "id": "uuid"
    }
  ],
  "total": 125
}
```

---

## Рекомендуемый JSON-шаблон полного ответа API

Так как пагинация должна использоваться внутри общей обёртки результата, итоговый ответ обычно выглядит так:

```json
{
  "value": {
    "items": [
      {
        "id": "uuid"
      }
    ],
    "total": 125
  },
  "isSuccess": true,
  "errors": []
}
```

## Как ссылаться из API-документа

В разделе `9. Возвращаемые данные` конкретного API-документа рекомендуется писать так:

```md
Метод возвращает пагинированный результат внутри общей result wrapper.
См. шаблоны:
- `Результаты claude/2026-05-05 - Шаблон обертки результата API.md`
- `Результаты claude/2026-05-05 - Шаблон результата пагинации API.md`
```

---

## Примечания

1. `items` содержит только элементы текущей страницы.
2. `total` содержит общее количество записей по фильтру без учёта размера страницы.
3. Если в конкретном API дополнительно используются `page`, `limit`, `offset` или сортировка, их нужно описывать в параметрах метода, а не в шаблоне `PaginatedResult`, если они не входят в сам response contract.
