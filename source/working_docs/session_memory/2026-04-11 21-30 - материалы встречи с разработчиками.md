## Принятые решения

- **Архитектура БД**: подтверждена модель Order/OrderLine (Request → RequestItems → Bookings) — BRD v3 явно закрепляет этот паттерн. Вариант «1 заявка = 1 бронь» не соответствует BRD и не рассматривается
- **CC Owner**: роль Obsolete — бронирование on-demand BP-техники происходит в DCT, не в этом инструменте; PSWS и DOA также Obsolete
- **CONFLICT-01 ЗАКРЫТ (10.04)**: FO может редактировать период брони до И после подтверждения; Requestor уведомляется автоматически; повторное подтверждение не нужно
- **Закрытие брони**: только вручную по кнопке (FR-NEW-32); при закрытии Requestor вводит фактические start/end time (для аналитики утилизации)
- **Transportation Responsible**: новая роль (Heavy Ops) — получает уведомление о транспортировке Unwheeled техники, подтверждает/отклоняет
- **Service Work Processor**: роль NOT DEFINED (OQ-NEW-C); временно исключена из Phase 1
- **Утилизация**: новое понятие из BRD v3 — каждый FO устанавливает порог 100% для каждого типа техники; данные из IVMS+Vega трекеров
