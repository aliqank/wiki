# **Инструмент бронирования HDV/HDE**

# Документ бизнес-требований

## 1 Введение

### 1.1 Цель

Настоящий документ определяет бизнес-требования к инструменту бронирования, позволяющему пользователям создавать заявки на оборудование HDV/HDE. Заявки могут включать несколько единиц оборудования, каждая из которых рассматривается как отдельное бронирование со своим процессом согласования.

### 1.2 Область применения

Инструмент будет поддерживать бронирование как оборудования, находящегося в собственности компании, так и оборудования, предоставляемого деловыми партнёрами. Он охватывает создание заявок, процесс согласования, отслеживание статусов, отчётность и интеграцию с внешними системами там, где это применимо.

## 2 Контекст

### 2.1 Текущие проблемы

- Отсутствие централизованного бронирования и взаимодействия между подразделениями по совместно используемым ресурсам
- Низкая прозрачность по общему количеству единиц и затратам
- Отсутствие стандартизированного процесса и руководящих принципов
- Отсутствие владельца(ев) процесса
- Недостаточная видимость из-за ручного мониторинга использования

### 2.2 Бизнес-цели

- Стандартизировать процесс заявок и бронирования.
- Обеспечить автоматическую маршрутизацию согласования на основе принадлежности парка оборудования.
- Обеспечить прозрачность и подотчётность в процессе бронирования.
- Обеспечить масштабируемость как для внутреннего, так и для оборудования партнёров.
- Владелец процесса — Логистика.

## 3 Глоссарий

**Заявка (Request)** — контейнер, объединяющий несколько бронирований оборудования.

**Обычная заявка (Regular Request)** — заявка, создаваемая Заявителем в инструменте бронирования HDV/HDE.

**Заявка на сервисные работы (Service Work Request)** — заявка, создаваемая автоматически в HDV/HDE через API на основе Рабочего задания, созданного Заявителем в системе JDE E1.

**Бронирование (Booking)** — отдельное бронирование в рамках заявки. Одно бронирование может содержать одну уникальную единицу оборудования. Обрабатывается индивидуально в рамках заявки.

**Оборудование (Equipment)** — отдельный актив (единица HDV/HDE), который может быть забронирован через систему. Каждая единица принадлежит парку и наследует ответственность за согласование от соответствующего Владельца парка. Единица оборудования имеет собственные атрибуты (например, ID оборудования, лицензия, статус использования и т.д.) и всегда рассматривается как отдельное бронирование при включении в заявку. Шаблон для оборудования будет различаться в зависимости от принадлежности парка: внутренний (собственность TCO) или внешний (собственность Делового партнёра).

**Парк (Fleet)** — логическая группа оборудования, принадлежащая Владельцу парка (для внутреннего: Техническое обслуживание, Строительство, TFM и т.д.; для внешнего — название делового партнёра).

**Владелец парка (Fleet Owner)** — лицо, ответственное за согласования в рамках парка.

**Согласующий (Approver)** — Владелец парка и/или Владелец центра затрат (ЦЗ), который подтверждает/отклоняет бронирования.

## 4 Заинтересованные стороны и роли

### 4.1 Заявитель (Requestor)

Все пользователи в сети TCO по умолчанию имеют роль Заявителя для бронирования оборудования внутреннего парка (HDV/HDE, принадлежащего TCO). Бронирование оборудования внешнего парка (HDV/HDE, принадлежащего ДП) доступно только пользователям с ролью «Инициатор RWA» в инструменте Digital Contractor Timesheet (DCT). Заявители могут:

1. Создавать обычную заявку
2. Подавать обычную заявку
3. Продлевать бронирование
4. Оставлять отзыв о забронированном оборудовании
5. Отслеживать использование забронированного оборудования за период бронирования, если оборудование имеет трекеры
6. Завершать бронирование досрочно (только для внешнего парка)

### 4.2 Обработчик заявок на сервисные работы (Service Work Processor)

Предоставление доступа управляется группой Azure Active Directory (AAD). Аналогично Заявителю, однако Обработчик заявок на сервисные работы работает с Заявками на сервисные работы, создаваемыми автоматически в инструменте бронирования HDV/HDE.

### 4.3 Владелец парка (Fleet Owner)

Для внутренних Владельцев парка предоставление доступа управляется группой AAD. Может существовать 2 и более групп AAD для управления внутренними Владельцами парка (отдельная группа для каждого парка, создаваемая Администратором). Владельцы парка могут:

1. Создавать новое оборудование в собственном парке (разрешено только внешним Владельцам парка)
2. Обновлять оборудование (только параметры, разрешённые для редактирования Администратором)
3. Удалять оборудование (мягкое удаление)
4. Подтверждать/отклонять заявки на бронирование оборудования собственного парка
5. Корректировать период бронирования до подтверждения
6. Заменять оборудование в бронировании
7. Досрочно завершать уже подтверждённые бронирования (только внутренний парк)
8. Замораживать/размораживать собственное оборудование от бронирования на определённый период или без даты окончания
9. Отслеживать использование собственного оборудования, если оно имеет трекеры

### 4.4 Владелец ЦЗ (включая ДПА)

Отдельной группы AAD для предоставления прав Владельца ЦЗ не предусмотрено. Инструмент HDV/HDE должен определять (через интеграцию с PSWS и DOA), может ли вошедший пользователь действовать как Владелец ЦЗ или его Делегированное полномочное лицо (ДПА). Владельцы ЦЗ могут:

1. Подтверждать/отклонять заявки на бронирование оборудования внешнего парка

### 4.5 Администратор (Administrator)

Роль Администратора предоставляется владельцам процесса — Логистике. Предоставление доступа управляется группой Azure Active Directory. Пользователи с ролью Администратора могут:

1. Создавать/редактировать внутренний парк и связывать его с группой AAD
2. Создавать/редактировать внешний парк и управлять внешними владельцами парка (отправлять приглашения, деактивировать учётные записи внешних пользователей)
3. Удалять парки
4. Создавать оборудование внутреннего парка
5. Обновлять параметры оборудования (расширенное редактирование)
6. Удалять оборудование (мягкое удаление)
7. Управлять шаблоном «Заявки»
8. Управлять шаблоном «Оборудования»
9. Получать доступ к кастомным отчётам
10. Получать доступ к панелям мониторинга использования, если оборудование имеет трекеры

## 5 Сущности

### 5.1 Оборудование

Все единицы оборудования должны иметь обязательный атрибут — парк. Этот атрибут определяет шаблон оборудования (в зависимости от внутреннего или внешнего парка), круг лиц, имеющих право на создание/редактирование/удаление (владельцы парка), а также процесс согласования бронирования.

Оборудование внутреннего парка имеет следующие параметры:

1. Базовая фиксированная информация (ID TCO, описание, сервисная зона, класс/категория, лицензия, серийный номер и т.д.)
2. Динамические (изменяемые) параметры: статус использования оборудования, ЦЗ/дивизион/группа/отдел, назначенное местоположение, ДП по техобслуживанию, контактный номер/email и т.д.
3. Технические характеристики оборудования (**фотография**, тип шасси, тип привода, грузоподъёмность, характеристики генератора/компрессора)
4. ID трекеров (при наличии: группа трекера WIALON, регистрационный номер трекера IVMS, ID устройства трекера Vega и т.д.)

### 5.2 Бронирование

Бронирование привязано к одной единице оборудования и имеет диапазон дат (дата/время). Несколько бронирований образуют одну заявку.

#### 5.2.1 Внутреннее бронирование

Бронирование оборудования, принадлежащего TCO (внутренний парк). Оборудование внутреннего парка требует только подтверждения со стороны Владельца внутреннего парка. Владелец парка может скорректировать период бронирования и/или заменить оборудование при наличии замены.

#### 5.2.2 Внешнее бронирование

Бронирование оборудования, предоставляемого партнёром (внешний парк). Оборудование внешнего парка требует следующих подтверждений:

1. Владелец ЦЗ или его ДПА
2. Владелец внешнего парка

### 5.3 Заявка

Заявки бывают двух типов: Обычная заявка и Заявка на сервисные работы. Тип влияет на шаблон заявки, обязательность заполнения параметров и процесс согласования.

#### 5.3.1 Обычная заявка

В обычной заявке Заявитель может добавить 2 и более единицы оборудования из любого парка — ограничения на принадлежность всего оборудования к одному парку нет. Каждая добавленная единица рассматривается как отдельное бронирование и подтверждается Владельцами парков по отдельности.

Система будет отдавать приоритет активам TCO (внутренний парк). При их недоступности будет предложена аренда у ДП (внешний парк) на основе заранее заданной матрицы решений (стоимость, надёжность, доступность).

Для оборудования внутреннего парка, добавленного в заявку, Заявитель должен указать период бронирования (дата/время).

Для оборудования внешнего парка, добавленного в заявку, Заявитель должен указать «Обоснование» и Центр затрат. Система должна автоматически заполнять поле «Центр затрат» значением ЦЗ Заявителя (получая информацию из PSWS); Заявитель может изменить предзаполненные данные вручную.

#### 5.3.2 Заявка на сервисные работы (в рамках Рабочего задания в JDE E1)

В отличие от обычной заявки, Заявки на сервисные работы создаются в системе автоматически в статусе «Черновик» после создания Рабочего задания в JDE E1 и подаются Обработчиком заявок на сервисные работы. Каждый «Шаг» в Рабочем задании создаётся как отдельная Заявка на сервисные работы в инструменте бронирования HDV/HDE. Обработчик назначает оборудование и подаёт заявку.

## 6 Функциональные требования

### 6.1 Управление пользователями и ролями

**FR-001:** Система поддерживает контроль доступа на основе ролей.

**FR-002:** Все пользователи в сети TCO имеют доступ к инструменту в роли Заявителя, однако для добавления оборудования внешнего парка в заявку пользователь должен быть членом группы AAD «Инициатор RWA».

**FR-003:** Администраторы и Обработчики заявок на сервисные работы определяются по принадлежности к соответствующим группам AAD.

**FR-004:** Система определяет наличие у пользователя прав Владельца ЦЗ или его ДПА в результате интеграции с внутренними системами: PSWS (TCO White Page) и DOA (Delegation of Authority).

### 6.2 Панель администратора

**FR-005:** Администратор может создавать парки (внутренние, внешние).

**FR-006:** Администратор может связывать внутренний парк с группой AAD, чтобы члены этой группы могли действовать в системе как Владельцы парка.

**FR-007:** Администратор может управлять владельцами созданных внешних парков: отправлять приглашения Деловому партнёру для создания учётной записи, деактивировать существующие внешние учётные записи.

**FR-008:** Администратор может обновлять существующие парки.

**FR-009:** Администратор может удалять существующие парки.

**FR-010:** Администратор может управлять шаблоном оборудования (отличается для внутренних и внешних парков): определять параметры, форматы (строка, число, булево значение, выпадающий список и т.д.), обязательность, доступность для редактирования владельцами.

**FR-011:** Администратор может управлять шаблоном заявки.

**FR-012:** Администратор может управлять шаблоном бронирования.

**FR-013:** Администратор может создавать оборудование внутреннего парка.

**FR-014:** Администратор может редактировать оборудование (расширенное редактирование).

**FR-015:** Администратор может удалять оборудование.

**FR-016:** Администратор имеет доступ ко всем панелям мониторинга и отчётам.

### 6.3 Управление оборудованием

**FR-017:** Владелец внешнего парка может создавать оборудование при заполнении всех обязательных параметров.

**FR-018:** Владелец парка должен указать «Парк» для оборудования; система позволяет выбрать только тот парк, Владельцем которого является пользователь.

**FR-019:** Владелец парка может редактировать (в пределах, разрешённых Администратором) оборудование своего парка. Примечание: один пользователь может быть Владельцем нескольких парков, если является членом соответствующих групп AAD.

**FR-020:** Владелец парка может удалять оборудование своего парка.

**FR-021:** Владелец парка может замораживать/размораживать собственное оборудование на определённый период или без даты окончания.

**FR-022:** Заявитель / Обработчик заявок на сервисные работы может оставить отзыв об оборудовании, бронирование которого подтверждено Согласующим(и), начиная с даты и времени начала бронирования.

### 6.4 Управление заявками

**FR-023:** Заявитель может создать заявку.

**FR-024:** Заявка имеет уникальный идентификатор и метаданные (дата, заявитель, статус и т.д.).

**FR-025:** Заявитель может просматривать детали заявки и её статус.

**FR-026:** Заявка может иметь статус: Черновик, Подана, В работе, Завершена.

**FR-027:** Заявитель может редактировать или отменить черновик заявки до подачи.

**FR-028:** Заявки, созданные системой автоматически (Заявки на сервисные работы, созданные через API), будут иметь статус «Черновик» до подачи Обработчиком заявок на сервисные работы.

**FR-029:** Управлять (подавать) Заявками на сервисные работы могут только пользователи с ролью Обработчика заявок на сервисные работы.

**FR-030:** Система поддерживает сохранение черновика (возможность продолжить позже).

### 6.5 Управление бронированиями

**FR-031:** Заявитель может добавлять/удалять несколько единиц оборудования в рамках одной заявки. Доступность оборудования в БД обновляется.

**FR-032:** Система отдаёт приоритет оборудованию внутреннего парка.

**FR-033:** Заявитель может добавлять оборудование внутреннего парка со статусом использования «Общее без условий» или «Общее с условиями».

**FR-034:** Система предлагает оборудование внешнего парка на основе заранее заданной матрицы решений (стоимость, надёжность, доступность). Кастомная логика — TBD.

**FR-035:** Заявитель может добавить оборудование внешнего парка в заявку только при условии членства в группе AAD «Инициатор RWA».

**FR-036:** При добавлении оборудования внешнего парка в заявку Заявитель должен указать «Обоснование».

**FR-037:** При добавлении оборудования внешнего парка в заявку поле «Центр затрат» должно быть заполнено для данного бронирования. Система автоматически заполняет параметр ЦЗ Заявителя (через интеграцию с PSWS); Заявитель может изменить предзаполненные данные.

**FR-038:** Каждая единица оборудования, добавленная в заявку, рассматривается как отдельное бронирование.

**FR-039:** Каждое бронирование имеет собственный уникальный ID, дату/время начала и окончания.

**FR-040:** Система проверяет доступность оборудования перед бронированием.

**FR-041:** Атрибуты оборудования (фотография, парк, описание, статус использования и т.д.) отображаются.

**FR-042:** Каждое бронирование имеет собственный жизненный цикл (Черновик, Подано, Подтверждено, Отклонено, Отозвано, Досрочно завершено, Завершено).

### 6.6 Процесс согласования (оборудование внутреннего парка)

**FR-043:** Система автоматически назначает согласующего на основе принадлежности парка.

**FR-044:** Если оборудование в бронировании принадлежит внутреннему парку, бронирование может быть подтверждено или отклонено пользователем, являющимся владельцем этого парка (членом соответствующей группы AAD).

**FR-045:** Владелец парка может подтверждать входящие бронирования оборудования своего парка.

**FR-046:** Владелец парка может заменять оборудование в бронировании на другое до или после подтверждения, если дата начала бронирования не наступила или дата окончания бронирования в будущем. Доступность оборудования в БД обновляется.

**FR-047:** Владелец парка не может заменить оборудование, если бронирование отозвано (Заявителем), досрочно завершено (Владельцем парка) или дата окончания бронирования в прошлом.

**FR-048:** Владелец внутреннего парка может корректировать диапазон дат бронирования до подтверждения. Доступность оборудования в БД обновляется.

**FR-049:** Владелец парка может отклонять входящие бронирования оборудования своего парка. Доступность оборудования в БД обновляется.

**FR-050:** Владелец парка может указывать причину/комментарий при отклонении.

### 6.7 Процесс согласования (оборудование внешнего парка)

**FR-051:** Если оборудование в бронировании принадлежит внешнему парку, бронирование сначала требует подтверждения Владельца ЦЗ в зависимости от указанного в бронировании центра затрат.

**FR-052:** Система автоматически определяет наличие у пользователя прав Владельца ЦЗ, используя информацию из PSWS.

**FR-053:** Система позволяет ДПА Владельцев ЦЗ подтверждать/отклонять бронирования. Доступность оборудования в БД обновляется при отклонении.

**FR-054:** Система автоматически определяет, может ли пользователь (ДПА) обрабатывать бронирование от имени Владельца ЦЗ, используя информацию из систем PSWS и DOA.

**FR-055:** Владелец ЦЗ/ДПА может указывать причину/комментарий при отклонении бронирования.

**FR-056:** После подтверждения бронирования Владельцем ЦЗ / ДПА система требует подтверждения Владельца парка (Делового партнёра).

**FR-057:** Владелец парка может подтвердить или отклонить бронирование. При отклонении может указать причину/комментарий. Доступность оборудования в БД обновляется при отклонении.

### 6.8 Управление жизненным циклом бронирования

**FR-058:** Заявитель / Обработчик заявок на сервисные работы может отозвать бронирование оборудования любого парка, если оно ещё не обработано (подтверждено/отклонено) Владельцем парка. Доступность оборудования в БД обновляется.

**FR-059:** Владелец внутреннего парка может досрочно завершить уже подтверждённое бронирование. При досрочном завершении может указать комментарий/причину. Доступность оборудования в БД обновляется.

**FR-060:** Заявитель / Обработчик заявок на сервисные работы может досрочно завершить уже подтверждённое бронирование. Доступность оборудования в БД обновляется.

**FR-061:** Заявитель / Обработчик заявок на сервисные работы может продлить ранее подтверждённое бронирование. Доступность оборудования в БД обновляется.

### 6.9 Управление статусами бронирований/заявок

**FR-062:** Бронирование получает статус «Подано» после подачи заявки.

**FR-063:** Бронирование получает статус «Подтверждено» после подтверждения Владельцем парка.

**FR-064:** Бронирование получает статус «Отклонено» после отклонения Владельцем парка.

**FR-065:** Бронирование оборудования внешнего парка получает статус «Частично подтверждено» после подтверждения Владельцем ЦЗ.

**FR-066:** Бронирование оборудования внешнего парка получает статус «Отклонено» после отклонения Владельцем ЦЗ.

**FR-067:** Статус бронирования возвращается в «Подано» после продления Заявителем / Обработчиком заявок на сервисные работы.

**FR-068:** Бронирование получает статус «Отозвано» после отзыва Заявителем / Обработчиком заявок на сервисные работы.

**FR-069:** Бронирование получает статус «Досрочно завершено» после досрочного завершения Заявителем / Обработчиком заявок на сервисные работы / Владельцем парка.

**FR-070:** Статус подтверждённого бронирования меняется на «В работе» при наступлении даты/времени начала бронирования.

**FR-071:** Статус подтверждённого бронирования меняется на «Завершено» после наступления даты/времени окончания бронирования.

**FR-072:** Заявка получает статус «Черновик» после сохранения в виде черновика Заявителем / Обработчиком заявок на сервисные работы.

**FR-073:** Заявка на сервисные работы получает статус «Черновик» после импорта из JDE E1.

**FR-074:** Заявка получает статус «В работе» при наличии хотя бы одного бронирования в статусе «В работе».

**FR-075:** Заявка получает статус «Завершена» после наступления максимальной даты/времени окончания среди всех бронирований.

### 6.10 Уведомления

**FR-076:** Система уведомляет Обработчика(ов) заявок на сервисные работы о создании Заявки на сервисные работы в системе через API (призыв к действию).

**FR-077:** Система уведомляет Владельца парка о подаче заявки Заявителем / Обработчиком на бронирование оборудования внутреннего парка (призыв к действию).

**FR-078:** Система уведомляет Владельца парка об отзыве бронирования оборудования внутреннего парка Заявителем / Обработчиком (информация).

**FR-079:** Система уведомляет Заявителя / Обработчика о результате подтверждения или отклонения бронирования оборудования внутреннего парка Владельцем парка (результат: успех или отказ).

**FR-080:** Система уведомляет Заявителя / Обработчика о досрочном завершении бронирования оборудования внутреннего парка Владельцем парка (результат: отказ).

**FR-081:** Система уведомляет Владельца парка о желании Заявителя / Обработчика продлить бронирование оборудования внутреннего парка (призыв к действию).

**FR-082:** Система уведомляет Владельца(ев) ЦЗ о подаче заявки Заявителем / Обработчиком на бронирование оборудования внешнего парка (призыв к действию).

**FR-083:** Система уведомляет Владельца ЦЗ об отзыве бронирования оборудования внешнего парка до получения подтверждения Владельца ЦЗ (информация).

**FR-084:** Система уведомляет Заявителя / Обработчика об отклонении Владельцем ЦЗ бронирования оборудования внешнего парка (результат: отказ).

**FR-085:** Система уведомляет Владельца парка о подтверждении Владельцем ЦЗ бронирования оборудования внешнего парка (призыв к действию).

**FR-086:** Система уведомляет Владельца ЦЗ и Владельца парка об отзыве Заявителем / Обработчиком бронирования оборудования внешнего парка до получения подтверждения Владельца парка, но после получения подтверждения Владельца ЦЗ (информация).

**FR-087:** Система уведомляет Заявителя / Обработчика об отклонении Владельцем парка бронирования оборудования внешнего парка (результат: отказ).

**FR-088:** Система уведомляет Заявителя / Обработчика о подтверждении Владельцем парка бронирования оборудования внешнего парка (результат: успех и призыв к действию — подать RWA в DCT).

**FR-089:** Система уведомляет Владельца парка о досрочном завершении Заявителем / Обработчиком уже подтверждённого бронирования оборудования внешнего парка (информация).

**FR-090:** Система уведомляет Владельца ЦЗ о желании Заявителя / Обработчика продлить уже подтверждённое бронирование оборудования внешнего парка (призыв к действию).

### 6.11 Поиск и отчётность

## 7 Нефункциональные требования

**Доступность:** Время работы системы — не менее 99,5%.

**Производительность:** Система должна поддерживать высокий объём запросов в час без деградации производительности.

**Безопасность:** Контроль доступа на основе ролей (RBAC). Система интегрируется с корпоративной аутентификацией (SSO).

**Соответствие требованиям:** Сохранение истории всех подтверждений/отклонений/отзывов/досрочных завершений.

**Масштабируемость:** Поддержка как внутренних сценариев использования, так и сценариев с внешними партнёрами.

**Удобство использования:** Интуитивный интерфейс как для заявителей, так и для согласующих.

## 8 Интеграции

### 8.1 JDE E1

Рабочие задания, созданные в JDE E1, должны импортироваться в инструмент HDV/HDE в виде Заявок на сервисные работы после присвоения Рабочему заданию определённого статуса (TBD). Рабочее задание может содержать несколько Шагов; каждый Шаг создаётся как отдельная Заявка на сервисные работы в инструменте бронирования HDV/HDE. Только Шаги определённых типов (BHOE, CDECK, DTRK, FORKL, FTRK-ХИНО, GDRV, GMLOG, MLIFT, VTRK и т.д.) будут импортироваться в HDV/HDE в виде Заявок на сервисные работы.

Системы должны иметь обратную интеграцию, позволяющую изменять статус «Шага» в JDE на основе изменения статуса импортированной «Заявки» в HDV/HDE или по ручным действиям Обработчика заявок на сервисные работы.

### 8.2 DCT (Digital Contractor Timesheet)

#### *8.2.1 Создание RWA / Дополнительного соглашения*

После получения всех согласований (от Владельцев ЦЗ и Владельца парка) на бронирование оборудования внешнего парка система должна создать черновик RWA в DCT (через POST API) и получить ID RWA (синхронно или асинхронно).

**Примечание:** Получение ID RWA может быть синхронным, если HDV/HDE передаст все обязательные атрибуты RWA, что позволит системе DCT присвоить ID. В противном случае на стороне инструмента HDV/HDE должен быть реализован API, который будет использоваться системой DCT: DCT передаст ID RWA и параметр заявки/оборудования (TBD).

После получения всех согласований (от Владельцев ЦЗ и Владельца парка) на продление бронирования оборудования внешнего парка система должна создать Дополнительное соглашение в DCT (через POST API). ID ранее созданного RWA содержится в теле запроса API.

#### *8.2.2 Получение данных с трекеров*

После оснащения оборудования внешнего парка трекерами система должна быть спроектирована для передачи данных в DCT, чтобы DCT мог сопоставлять фактические рабочие часы с часами, отчитанными Деловым партнёром.

### 8.3 PSWS (TCO White Page)

Если оборудование, добавленное в бронирование, относится к внешнему парку, сначала требуется согласование Владельца ЦЗ, указанного в заявке. При входе пользователя в инструмент HDV/HDE система должна определить, является ли данный пользователь Владельцем ЦЗ для какого-либо оборудования внешнего парка (ДП), ожидающего согласования Владельца ЦЗ. Если да — система должна явно отображать список такого оборудования, ожидающего согласования. Информация о Владельцах ЦЗ предоставляется из PSWS.

Информация из PSWS также необходима для сохранения предпочтительного email-адреса пользователя, требуемого для определения корректных получателей уведомлений.

### 8.4 DOA (Delegation of Authority)

При входе пользователя в инструмент HDV/HDE система должна определить, является ли данный пользователь ДПА Владельца ЦЗ для какого-либо оборудования внешнего парка (ДП), ожидающего согласования Владельца ЦЗ. Если да — система должна явно отображать список оборудования, ожидающего согласования Владельца ЦЗ, чтобы ДПА мог обработать заявку.

### 8.5 DataLake / PI

Из DataLake будет поступать информация об использовании с трекеров IVMS и WIALON (список источников может быть расширен при оснащении новыми трекерами). В списке параметров оборудования будет содержаться «ID трекера», позволяющий системе сопоставлять имеющееся оборудование с данными DataLake об использовании и местоположении.
