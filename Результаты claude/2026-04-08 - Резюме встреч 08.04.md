## Встреча 1 — Daily meeting (15:00)
**Тема:** Внешний флот бизнес-партнёров; уточнение Long-term rent  
**Участники:** команда проекта, Логистика, Майнтененс, Балкинже (контрактная команда)

### Ключевые решения

#### 1. Бронирование внешней техники (BP) — модель «витрина»
- **Решено:** в Phase 1 бронирование через Booking Tool распространяется **только на внутренний флот** (TCO Own + Long-term rented).
- BP-техника отображается в системе как **каталог (витрина)** без возможности бронирования.
- Причина: контракты с BP разные, условия vary, ставки конфиденциальны (видит только contract donor). Показывать цены/ставки **нельзя**.
- Дальнейший процесс после просмотра витрины: Requestor видит контрактного владельца и выходит на него **по email** (оффлайн), после чего всё оформляется через DCT.

#### 2. Состав каталога BP
- В каталоге — только техника **физически на Тенгизе** (не с удалённых площадок).
- Каждая запись каталога содержит: перечень техники по типам + контактное лицо (contract owner) + условие (shared/не shared в рамках контракта).
- Ставки (rates) — **не отображаются**.

#### 3. Что входит во внутренний флот (Available for booking)
- TCO **Own** (собственная техника ТШО) — ✅
- **Long-term rented** (долгосрочная аренда у BP, техника де-факто в управлении ТШО) — ✅ (без дополнительных согласований)
- **On-demand rented** (BP, по запросу) — ❌ фазе 1 только витрина

**Уточнение:** Long-term rented техника добавляется **во внутренний список флота** (не в витрину), т.к. у ТШО уже есть авторизация на её использование.

#### 4. Assigned-техника — новый подход к видимости
- Ранее: Assigned не отображается Requestor-у.
- **Новое решение:** Assigned-техника **видна всем** пользователям, но **бронировать** её могут только пользователи с определёнными правами (FO-уровень, конкретный список, настраивается admin).
- При бронировании Assigned — обязательно поле **Justification**.
- Пример: снегоуборочная машина в аэропорту (Assigned) может быть запрошена при ЧС, но только уполномоченным лицом.

#### 5. Делегирование полномочий FO
- FO должен уметь самостоятельно (без IT) делегировать свои права **любому сотруднику TCO** на указанный период.
- Делегат получает доступ на срок начала–конца; по истечении — автоматически отзывается.
- Объём делегирования настраивается: создание заявок / утверждение заявок (галочки).
- Аналог уже реализован в системе материальных пропусков TCO.

#### 6. IVMS/GPS-датчики — только TCO-флот
- Датчики Teltonika/IVMS закупаются **только для TCO-флота**.
- Для BP — требуется отдельная договорённость на уровне контрактов.
- Без датчиков утилизацию BP-техники видеть нельзя.

## Встреча 2 — Requirements Gathering / UI Design Review (16:01)
**Тема:** Демонстрация и разбор Figma-макетов UI; анализ Master Fleet File  
**Участники:** команда проекта, дизайнер Женя, Асылбек, Ерлан, Турсынбек, Субек, Думан

### Часть A — Демонстрация Figma-макетов

#### Экран 1: «Мои заявки» (Requestor)
- Список заявок с фильтрами: статус / дата подачи / период бронирования.
- Кнопка «Добавить заявку» → открывается модальное окно выбора техники.
- **Фидбэк:** разделение по типу подвижности (Self-propelled motorized и т.д.) убрать из UI Requestor-а — пользователи не знают терминологии. Показывать просто список типов техники (погрузчики, компрессоры, краны и т.д.).
- **Фидбэк:** стационарное оборудование — не отображать в поиске у Requestor-а.

#### Экран 2: Модальное окно выбора техники
- Фильтры должны быть **динамическими** — для каждого типа техники свои параметры (грузоподъёмность для погрузчика, давление для компрессора и т.д.).
- В таблице результатов добавить: **госномер** и **TCO-номер** (equipment number).
- Поиск по названию/модели — оставить.
- **Фидбэк:** при наведении на строку техники — показывать **фото оборудования** (всплывающее).

#### Экран 3: Форма заявки (после добавления техники)
- Поле **Work Order** — 7-значное число, обязательное для Maintenance/Railroad/Operations.
- Поле **Location** — для SCM Logistics (у них нет GDE Work Order); логика: если выбран флит SCM Logistics — поле Work Order неактивно, показывается поле Location.
- Поле **Описание работ** — обязательное, ограничение ~50 символов.
- Поле **Комментарии** — опциональное, без жёсткого лимита.
- Кнопки: Сохранить в черновик / Отправить / Отмена.

#### Экран 4: Интерфейс Fleet Owner — Список заявок
- Только заявки своего флота.
- Таймер ответа на заявку.
- Поля: номер заявки, дата создания, Requestor, период, приоритет.
- Открыть заявку → возможность заменить конкретную единицу техники / подтвердить / отклонить.

#### Экран 5: Раздел «Оборудование» (FO)
- Поиск по TCO-номеру и госномеру.
- Левый сайдбар: сводка статусов парка (всего / в работе / свободно / в ремонте).
- Центральная карта: оборудование с геолокацией.
- Правый список: таблица техники со статусами.
- Статус ремонта: подтягивать из JDE (SQL база), показывать статус + **предполагаемую дату выхода из ремонта** (поле Planet/Planned date в JDE).
- Техника в ремонте — отображать серым, недоступна для выбора, но видна.
