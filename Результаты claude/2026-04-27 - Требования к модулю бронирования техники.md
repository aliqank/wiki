## 1. Введение

### 1.1 Назначение документа

Документ описывает функциональные требования к **модулю бронирования техники** в составе HDV/HDE Booking Tool. Охватывает создание заявок, управление бронированиями, цепочку согласования, жизненный цикл бронирования и связанные уведомления. Не включает: Admin Panel, дашборд утилизации, GIS-карту, отчётность — для них предусмотрены отдельные модули.

### 1.2 Область применения

Модуль обеспечивает бронирование техники следующих типов собственности:
- **TCO Owned** — техника в собственности TCO
- **Long-term rented** — долгосрочно арендованная техника (обрабатывается как внутренний флот)

**Вне области применения (Phase 1):** On-demand BP (Showcase) — отображается как каталог/витрина без возможности бронирования.

## 2. Глоссарий

| Термин | Определение |
|--------|-------------|
| **Request** | Заявка — контейнер, объединяющий несколько бронирований (по одному на единицу техники). Создаётся одним Requestor-ом. |
| **Regular Request** | Заявка, созданная Requestor-ом вручную в системе. |
| **Service Work Request (SWR)** | Заявка, автоматически созданная системой на основе Work Order из JDE E1 при достижении шагом WO статуса 55. Видна только пользователям с ролью SWP. |
| **Booking** | Отдельное бронирование одной единицы техники внутри заявки. Обрабатывается независимо. |
| **Fleet Owner (FO)** | Ответственный за парк техники; согласует/отклоняет бронирования своего парка. |
| **Mobilization** | Период подготовки/движения техники до прибытия на объект. Бронирование начинается с начала мобилизации. |
| **Assigned** | Техника, закреплённая за конкретным подразделением. Видна всем, бронируется только авторизованными Admin-ом пользователями с обязательным обоснованием. |
| **Shared without Conditions** | Техника общего пользования без дополнительных условий. |
| **Shared with Conditions** | Техника общего пользования; при бронировании обязательно заполнение поля Justification (обоснование). |
| **Booking Snapshot** | Снимок ключевых атрибутов техники на момент подтверждения бронирования. |
| **Transportation Responsible** | Роль, ответственная за транспортировку несамоходной (Unwheeled) техники. |
| **SWP (Service Work Processor)** | Пользователь с ролью для управления SWR (заявками из JDE). |
| **Default Work Order** | Опция для команд, не работающих в JDE (напр. Logistics): позволяет создать заявку без указания номера JDE WO. |
| **Default Work Center** | Аналогичная опция для команд без Work Center в JDE. |

## 3. Роли

| Роль | Участие в модуле бронирования |
|------|-------------------------------|
| **Requestor** | Создаёт и управляет Regular Request; закрывает бронирования; просматривает историю заявок |
| **Service Work Processor (SWP)** | Управляет Service Work Requests (из JDE); может подавать, продлевать, аннулировать SWR |
| **Fleet Owner (FO)** | Согласует/отклоняет бронирования своего парка; корректирует период; фиксирует старт мобилизации; завершает бронирования |
| **Transportation Responsible** | Подтверждает/отклоняет транспортировку несамоходной техники |
| **Administrator** | Авторизует пользователей для бронирования Assigned-техники; настраивает параметры системы |

## 4. Сущности модуля

### 4.1 Request (Заявка)

Заявка является агрегирующим объектом для одного или нескольких бронирований.

**Обязательные поля заявки:**

| Поле | Правило |
|------|---------|
| Work Order (JDE) | Обязательно для Maintenance / Railroad / Operations. Опционально для Logistics. Для SCM Logistics заменяется полем Location. |
| Work Center (WC) | Обязательно для JDE-парков; не требуется для Logistics. |
| Location | Текстовое поле; заменяет WO для SCM Logistics. |
| Work Description | Обязательно, ~50 символов. |
| Priority (P1–P4) | Атрибут заявки / WO целиком, а не отдельного бронирования. |
| Comments | Опционально. |

**Дополнительные механизмы заполнения WO:**
- Блок «Выбрать Work Order из JDE» на странице Submit Request — список WO загружается из JDE E1 через прямое API; при выборе автоматически генерируется черновик (FR-NEW-48).
- **Default Work Order** — чекбокс для команд без JDE WO (Logistics и др.): при включении система не требует номер WO (FR-NEW-51).
- **Default Work Center** — аналогичный чекбокс для команд без WC (FR-NEW-51).

**Статусы заявки (BookingRequests.status):**

| Статус | Условие перехода |
|--------|-----------------|
| Draft | Заявка сохранена как черновик |
| Submitted | Заявка отправлена Requestor-ом / SWP-ом |
| InProgress | Хотя бы одно активное (не Declined) бронирование перешло в InProgress |
| Completed | Последнее активное (не Declined) бронирование закрыто вручную |
| Cancelled | Заявка отменена заявителем до отправки |

> Агрегированный статус заявки рассчитывается автоматически на основе статусов входящих бронирований (FR-NEW-17).

**Формат номера заявки:** `REQ-YYYY-NNNNN` — порядковый номер генерируется как SERIAL (INT), год берётся из `createdAt`. Отображается в UI, хранится как INTEGER в поле `requestNumber`.

**Поведение транспортной брони (Unwheeled):** транспортная бронь создаётся FO в рамках **той же заявки** (тот же `requestId`). Атрибуция FO фиксируется только на уровне транспортной брони, шапка заявки остаётся от имени Requestor-а.

**Ограничения (настраиваются через Admin Panel):**
- Горизонт бронирования: 1 месяц вперёд.
- Максимальная длительность: 1 неделя.

### 4.2 Booking (Бронирование)

Бронирование привязано к одной единице техники и имеет период (дата/время начала — конца).

**Ключевые атрибуты бронирования (Bookings):**

| Поле | Описание |
|------|---------|
| id | UUID, уникальный идентификатор |
| requestId | Ссылка на родительскую заявку |
| equipmentId | ID единицы техники (внешний, без FK-ограничения) |
| fleetId | ID парка техники (внешний; хранится как исторический атрибут) |
| assignedFleetOwnerId | Текущий ответственный FO (внешний; обновляется при делегировании) |
| status | Статус бронирования |
| startDt | Начало бронирования = запланированное начало мобилизации |
| endDt | Окончание бронирования |
| mobilizationStartedAt | Фактический старт мобилизации — проставляется кнопкой FO |
| justification | Обоснование; обязательно по бизнес-логике для Assigned и SharedWithConditions |
| transportBookingId | Self-ref FK на транспортную бронь (только для unwheeled-техники; бронь в том же requestId) |
| declineReason | Причина отклонения (обязательна при переходе в Declined) |
| terminateReason | Причина завершения (обязательна при переходе в Terminated) |
| closedBy / closedAt | Кто и когда закрыл бронирование |
| closeComment | Необязательный комментарий заявителя при закрытии |

> `justification` — НЕ ограничение на уровне БД (`nullable`); проверяется в приложении в зависимости от shareType техники.

**Статусы бронирования (Bookings.status):**

| Статус | Переход |
|--------|---------|
| Draft | При сохранении заявки как черновика |
| Submitted | При отправке заявки; при продлении Requestor/SWP-ом |
| Confirmed | FO подтвердил бронирование |
| TransportConfirmed | FO привязал транспортную бронь (`transportBookingId` заполнен); **только для unwheeled-техники** |
| Declined | FO отклонил бронирование |
| Revoked | Requestor/SWP аннулировал до обработки FO |
| Terminated | FO или Requestor/SWP принудительно завершил подтверждённое бронирование |
| InProgress | FO нажал «Mobilization started» (фиксирует `mobilizationStartedAt`) |
| Closed | Бронирование закрыто вручную через кнопку «Close» |
| EquipmentChanged | FO предложил замену техники; предыдущие `equipmentId`/`fleetId` сохранены в `previousSnapshot` |
| Extended | Бронирование продлено; прежний `endDt` сохранён в `previousSnapshot` |

> Все переходы статусов — **только ручные** (нет автоматических переходов по дате/времени).

**История переходов (BookingStatusHistories):** при каждом изменении статуса создаётся запись с `oldStatus → newStatus`, `changedBy`, `changedAt`, `comment`. Поле `previousSnapshot JSONB` фиксирует состояние до перехода для статусов `EquipmentChanged`, `Extended`, `TransportConfirmed` и при откате транспорта. **Заменяет концепцию Booking Snapshot** (OQ-37 — закрыт через эту механику).

**Транспортный откат:** если транспортная бронь (на которую ссылается `transportBookingId`) отменяется (Declined / Terminated / Revoked) — приложение возвращает unwheeled-бронь в `Confirmed` и обнуляет `transportBookingId`; в `previousSnapshot` фиксируется обнулённый ID.

### 5.5 Цепочка согласования (несамоходная / Unwheeled техника)

Трёхэтапный процесс для несамоходной (Unwheeled) техники:

```
Requestor → FO (подтверждение техники → статус Confirmed)
         → FO создаёт транспортную бронь в рамках той же заявки
           (транспортная бронь: отдельная запись в Bookings с тем же requestId)
         → Transportation Responsible (подтверждает транспортировку)
         → FO (финальное подтверждение → статус TransportConfirmed)
         → FO нажимает «Mobilization started» → статус InProgress
```

**Архитектурное решение (OQ-DB-11 — CLOSED 2026-04-27):** транспортная бронь создаётся в рамках **того же `requestId`**, что и unwheeled-бронь. Связь реализована через поле `transportBookingId` (self-referencing FK в таблице `Bookings`). Отдельная таблица `TransportRequests` не нужна.

| ID | Требование | Статус |
|----|-----------|--------|
| FR-NEW-29 | Трёхэтапный процесс для Unwheeled: Requestor → FO → Transportation Responsible → FO финальный | Confirmed |
| FR-NEW-29a | FO создаёт транспортную бронь (отдельная запись Bookings) в рамках той же заявки; привязывает через `transportBookingId`; статус unwheeled-брони → `TransportConfirmed` | Confirmed |
| FR-NEW-29b | Если транспортная бронь отменяется — система возвращает unwheeled-бронь в `Confirmed`, `transportBookingId` обнуляется | Confirmed |
| FR-NEW-30 | Если транспорт недоступен — FO предлагает ближайшую доступную дату | Pending |

### 5.7 Жизненный цикл бронирования (полная схема переходов)

```
                    ┌─────────┐
                    │  Draft  │◄── SWR из JDE (авто)
                    └────┬────┘
       Отмена до отправки │ Submit (Requestor / SWP)
    ┌───────────┐    ┌────▼────────┐
    │ Cancelled │    │  Submitted  │
    └───────────┘    └──┬─────────┘
                        │
        ┌───────────────┼──────────────────────┐
   FO: Confirm     FO: Decline     Requestor/SWP: Revoke
  ┌─────▼──────┐  ┌────▼──────┐   ┌────▼──────┐
  │ Confirmed  │  │ Declined  │   │  Revoked  │
  └──┬────┬───┘  └───────────┘   └───────────┘
     │    │
     │    └── FO: заменить технику
     │         ┌──────────────────┐
     │         │ EquipmentChanged │  (previousSnapshot: старый equipmentId)
     │         └──────────────────┘
     │
     │  [только unwheeled]
     │  FO привязывает транспорт
     │  ┌────────────────────┐
     │  │ TransportConfirmed │
     │  └────────┬───────────┘
     │           │ FO: Mobilization started
     └───────────┘
          │ FO: Mobilization started
    ┌─────▼──────┐
    │ InProgress │
    └──┬──────┬──┘
       │      │  Requestor/SWP: продлить
       │      │  ┌──────────┐
       │      └─►│ Extended │  (previousSnapshot: старый endDt)
       │         └──────────┘
       │
 ┌─────┴────────────────────────────┐
 │ Terminate (FO или Requestor/SWP) │
 └─────┬────────────────────────────┘──── Close (ручной) ──►┌────────┐
 ┌─────▼──────┐                                              │ Closed │
 │ Terminated │                                              └────────┘
 └────────────┘
```

> `EquipmentChanged` и `Extended` — промежуточные статусы, фиксирующие событие замены/продления. После перехода бронирование продолжает жизненный цикл со своего нового состояния (Confirmed / InProgress).
