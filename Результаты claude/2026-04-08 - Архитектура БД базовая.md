# Архитектура БД — базовая
**Дата:** 2026-04-08
**Тип документа:** Data Model v1
**Технология:**
**Scope:** Phase 1 · Внутренний флот (Cat 1) · Без внешних BP

> **Соглашения:**
> - Типы: `string`, `number`, `bool`, `Date`, `enum`, `ObjectId (ref)`
> - `*` — обязательное поле
> - Вложенные объекты обозначены отступом или `{ ... }`

---

## Обзор коллекций

| Коллекция | Назначение | Ключевые связи |
|-----------|-----------|----------------|

## 3. `equipment_types`

Справочник типов техники и определение динамических полей характеристик.

| Поле | Тип | Описание |
|------|-----|----------|
| `_id` | ObjectId | |
| `code` * | string | Уникальный код: `FORKLIFT`, `GENERATOR`, `COMPRESSOR`, `CRANE`, … |
| `nameRu` * | string | Отображаемое название (RU) |
| `icon` | string | Slug иконки |
| `specSchema` | SpecField[] | Массив описаний характеристик (см. ниже) |

**Вложенный объект `SpecField`:**

| Поле | Тип | Описание |
|------|-----|----------|
| `key` | string | Ключ: `load_capacity_t`, `power_kw`, `pressure_bar`, … |
| `labelRu` | string | Отображаемое название |
| `unit` | string | Единица измерения: `т`, `кВт`, `bar`, `м³/ч` |
| `dataType` | enum | `number` · `string` · `range` |
| `isRequired` | bool | |
| `filterEnabled` | bool | Использовать ли в фильтрах каталога |

**Пример записи:**
```
{ code: "FORKLIFT", nameRu: "Погрузчик",
  specSchema: [
    { key: "load_capacity_t", labelRu: "Грузоподъёмность", unit: "т",
      dataType: "number", filterEnabled: true }
  ]
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `_id` | ObjectId | |

| `requestorId` * | ObjectId (ref: users) | Кто подал |
| `equipmentId` * | ObjectId (ref: equipment) | Запрошенная единица |
| `fleetId` * | ObjectId (ref: fleets) | Флот FO (денормализовано для фильтрации) |
| `targetFoUserId` * | ObjectId (ref: users) | Конкретный FO, которому адресован запрос |
| `periodStart` * | Date | Начало бронирования |
| `periodEnd` * | Date | Конец бронирования |
| `workOrderNumber` * | string | JDE / GDE Work Order № |
| `priority` * | enum | `P1` · `P2` · `P3` · `P4` |
| `description` | string | Описание работ |
| `status` * | enum | `draft` · `pending_fo` · `action_required` · `confirmed` · `in_progress` · `completed` · `rejected` · `cancelled` |
| `rejectionReason` | string | Причина отказа FO (обязательна при status=rejected) |
| `rejectedAt` | Date | |
| `confirmedAt` | Date | |
| `completedAt` | Date | |
| `completedBy` | enum | `requestor` · `fleet_owner` |
| `transportAssignment` | TransportAssignment | Назначенный транспорт (для стационарной техники) |
| `foTimeoutAt` | Date | Дедлайн ответа FO (рассчитывается при status→pending_fo) |

**Вложенный объект `TransportAssignment`:**

| Поле | Тип | Описание |

> **Рекомендация:** Обсудить с командой до начала разработки.

## Схема связей (ERD — текстовый вид)

```
users ──────────────────────────────────────────────────┐
  │                                                      │
  │ (fleetId)                                           │ (requestorId, targetFoUserId)
  ▼                                                      ▼
fleets ──── (fleetId) ──── equipment                requests
                │                │                       │
       equipment_types      (equipmentId)          (requestId)
                                 │                       │
                                 └──── bookings ─────────┘
                                           │
                                  booking_extensions
```

## Примечания для разработки

| # | Тема | Рекомендация |
|---|------|-------------|
| 1 | **Multi-item request** | R-26 требует несколько единиц в одной заявке. Решить: одна Request = один item (текущая модель) + `request_groups`, или вложенный массив items в одном документе. Обсудить до старта. |
| 2 | **Блокировка при создании** | При создании Request — немедленно резервировать слот (мягкая блокировка) или только при подтверждении? Избежать race condition при параллельных заявках на одну единицу. |
| 3 | **MongoDB TTL** | Для `notifications` — TTL index (напр., 90 дней). `audit_logs` — без TTL (compliance). |
| 4 | **Conflict check query** | Индекс на `bookings(equipmentId, status, periodStart, periodEnd)` для быстрой проверки доступности. |
| 5 | **Status machine** | Реализовать как explicit state machine в backend (не просто поле в БД), чтобы исключить невалидные переходы. |
| 6 | **Денормализация** | `fleetId` в `requests` — намеренная денормализация для упрощения запросов. При смене FO-владельца парка — учесть. |
