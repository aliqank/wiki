## 1. GIS-карта и мониторинг техники

### Решения
- **Направление движения** и **скорость** — отображать для техники с GSM-трекерами. LoRaWAN (батарейка, 3 раза/день) — направление не отображается из-за редкой синхронизации
- **Топливо** — **НЕ отображать**: телематические данные по топливу не будут поступать
- **Исторический маршрут** — отображать (желательно), за 7 дней
- **Данные при клике на технику** — отображать всё, что приходит с датчиков (по последней синхронизации); список корректировать по фидбэку бизнеса в будущем
- GIS-карта полностью на стороне команды **GIS** (iframe в Booking Tool). Команда Booking Tool передаёт требования

### Ожидаемые данные от трекеров (IVMS)
Скорость (`speed`), координаты (`latitude`/`longitude`), направление (`heading`), моточасы, пробег (`odometerKilometres`), зажигание (`ignitionOn`), заряд батареи

## 2. Дашборд утилизации

### Подтверждены решения
- 3 таба: **по моточасам / по километражу / комбинированный**
- Градиентная закраска по **проценту факта к плану** (план задаётся для каждой единицы техники)
- Фильтр по **рабочим центрам** — добавлен
- Фильтр **принадлежность** (own / long-term rented) — добавлен
- Отображение по **дням** и по **месяцам**
- Поля: плановая утилизация, фактическая утилизация, **дни на ремонте**, среднее значение
- Интерфейс одобрен как визуально нормальный

### Новое требование
> **D-NEW-1:** Добавить в дашборд утилизации **количество бронирований за выбранный период** рядом со средней утилизацией. Позволяет анализировать связь между загруженностью техники и утилизацией (высокая утилизация при малом количестве бронирований vs наоборот).

### Не нужны
- Круговые диаграммы, пироги и другие сложные графики — достаточно цифр/фактов

## 4. Карточка оборудования — обязательность полей

### Контекст
Обсуждались поля при добавлении техники в систему. Проблема: у BP-техники многие поля (TCO-номер, госномер, ВИН, серийный номер, год выпуска) могут отсутствовать.

### Решение
- **Единая база данных** для TCO-техники и BP-техники (подтверждено)
- Для BP-техники ряд полей — **необязательные** (null допустим):

| Поле | TCO | BP (long-term rented) |
|---|---|---|
| Категория / подкатегория | Обязательно | Обязательно |
| Производитель / модель | Обязательно | Обязательно |
| Принадлежность | Обязательно | Обязательно |
| TCO (ТШО) номер | Обязательно | **Необязательно** |
| Гос. номер | Необязательно | **Необязательно** |
| ВИН / серийный номер | Необязательно | **Необязательно** |
| Год выпуска | Рекомендуется | **Необязательно** |
| Сервисный участок | Необязательно | **Необязательно** |
| Компания по ремонту | Желательно | Желательно |

- **Компания по ремонту** — хранить **желательно**: у одной техники могут быть разные подрядчики по видам работ (пример: гидросистема — Energstim, вытяжение — DAS)
- **Операционный статус** — убирается (уже было решено ранее); остаются статус ремонта и статус заморозки

### Уточнение по пожарным машинам (Assigned-техника)
Пожарные машины (и другие Assigned) — техника непередаваемая. Возможно, некоторые типы Assigned-техники стоит **исключить из фильтрации для Requestor** (характеристики им не нужны). Асылбек скорректирует при обновлении таблицы характеристик.
