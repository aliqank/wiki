# ТЗ на макет: Административная панель — Управление типами техники

**Дата:** 2026-04-24
**Для кого:** Дизайнер (Figma-макет)
**Подготовил:** Тельман Нуржанов SA (на основе БД Equipment-блок v1 и BRD v11)

---

## Назначение документа

Документ описывает экраны, модальные окна и навигационную структуру Admin Panel для системы HDV/HDE Booking Tool.

**Что описывает:** состав элементов, состояния, поведение, взаимодействия внутри Admin Panel.
**Что НЕ описывает:** визуальный стиль (следовать существующей дизайн-системе), экраны ролей Requestor/FO, API.

**Приоритет реализации макета:**
- Раздел «Типы техники» — реализовать полностью (все экраны и модалки)
- Остальные разделы — заглушки (каждый с отдельной страницей)

---

## 1. Общая структура Admin Panel

### 1.1 Макет-оболочка (shell)

**Верхний хедер (всегда виден):**
- Логотип / название системы слева
- Имя пользователя (Admin) + кнопка выхода справа

**Левый сайдбар (навигация):**

| # | Раздел | Иконка-подсказка | Статус в макете |
|---|--------|-----------------|-----------------|
| 1 | Типы техники | список с тегом | **Реализовать** |
| 2 | Флоты | дерево/группа | Заглушка |
| 3 | Справочники | книга/справочник | Заглушка |
| 4 | Доступ к Assigned технике | замок/ключ | Заглушка |
| 5 | Системные параметры | шестерёнка | Заглушка |
| 6 | Пользователи и роли | люди | Заглушка |
| 7 | Аудит | журнал/история | Заглушка |

**Активный раздел** выделен в сайдбаре. Содержимое отображается в основной рабочей зоне справа.

### 1.2 Страница-заглушка (для разделов 2–7)

Каждый неактивный раздел при переходе показывает страницу-заглушку (не просто заблокированную кнопку).

Содержимое заглушки:
- Название раздела (h1)
- Краткое описание назначения (1–2 строки)
- Метка / бейдж «В разработке»
- Список подразделов (если есть) — также с меткой «В разработке»

**Примеры текстов заглушек:**

| Раздел | Описание |
|--------|----------|
| Флоты | Управление парками техники, назначение Fleet Owner через AAD-группы |
| Справочники | Единицы измерения, подрядчики ТО, Work Centers, категории, производители, локации |
| Доступ к Assigned технике | Авторизация конкретных пользователей на бронирование закреплённой (Assigned) техники |
| Системные параметры | Тайм-аут ответа Fleet Owner (24/48 ч), горизонт бронирования, максимальная длительность брони |
| Пользователи и роли | Управление ролями (Admin, Service Work Processor), командные email-адреса флотов |
| Аудит | Полная история всех изменений в системе — заявки, бронирования, настройки |

## 2. Экран AP-01: Список типов техники

**Маршрут:** Admin Panel → Типы техники

**Назначение:** просмотр, поиск и управление справочником типов техники. Каждый тип определяет набор динамических параметров, которые автоматически отображаются в карточке техники, форме заявки и фильтрах поиска.

### 2.1 Элементы экрана

**Хедер страницы:**
- Заголовок: «Типы техники»
- Кнопка «+ Добавить тип» (primary, правый верхний угол) — переход на AP-02 (режим создания)

**Панель управления над таблицей:**
- Поле поиска по названию типа

**Таблица типов техники:**

| Колонка | Источник данных | Примечание |
|---------|----------------|------------|
| ≡ | — | Drag handle для изменения порядка (sortOrder). Tooltip: «Порядок влияет на список в интерфейсе» |
| Название типа | EquipmentTypes.name | |
| Класс | HDE / HDV | Из справочника |
| Тип мобильности | EquipmentTypes.mobilityType | Отображать русским названием (см. п. 5.1) |
| Требует транспорт | EquipmentTypes.requiresTransport | Иконка ✓ (да) / — (нет) |
| Work Center | Код WC из справочника | Может быть пусто |
| Спец. параметров | COUNT(EquipmentTypeProperties) | Число; при наведении — tooltip с перечислением |
| Единиц техники | COUNT(Equipments) | Число; информационно |
| Действия | — | Три иконки: Редактировать / Копировать / Удалить |

**Поведение строк:**
- Клик на строку → переход на AP-02 (режим редактирования)
- Drag & drop строки → изменение sortOrder (с сохранением без дополнительного подтверждения)

**Действие «Копировать»:**
- Создаёт дублирующую запись типа с именем «[Оригинал] (копия)»
- Копирует все базовые параметры и все специфические параметры
- Открывает AP-02 для нового типа в режиме редактирования (чтобы сразу переименовать)

**Действие «Удалить»:**
- Если «Единиц техники» = 0 → диалог подтверждения → soft delete
- Если «Единиц техники» > 0 → кнопка заблокирована, tooltip: «Нельзя удалить: к типу привязано N единиц техники»

**Пустое состояние (нет типов):**
- Иконка + текст: «Типы техники не добавлены»
- Кнопка «Добавить первый тип»

## 3. Экран AP-02: Карточка типа техники

**Маршрут (создание):** AP-01 → кнопка «+ Добавить тип»
**Маршрут (редактирование):** AP-01 → клик на строку или иконка «Редактировать»

**Два режима:** «Новый тип техники» / «Редактировать: [Название]»

### 3.1 Хедер карточки

- Хлебные крошки: «Типы техники → [Название]» (или «Новый тип» при создании)
- Кнопка «Копировать тип» (вторичная, рядом с хлебными крошками) — действие аналогично AP-01
- Кнопки управления (правый угол): **«Отменить»** (выйти без сохранения) | **«Сохранить»** (primary)

---

### 3.2 Блок A: Базовые параметры

Одинаковы для всех типов техники. Всегда отображаются вверху карточки.

| Поле | Элемент UI | Обязательно | Описание / Значения |
|------|-----------|-------------|---------------------|
| Название типа | Text input | Да | Уникальное. Пример: «Компрессор», «Экскаватор», «Самосвал» |
| Класс техники | Select | Да | HDE / HDV (справочник) |
| Тип мобильности | Select | Да | 4 значения — см. п. 5.1 |
| Требует транспортировку | Toggle (Да / Нет) | Да | TRUE = в процессе бронирования запускается подпроцесс запроса транспорта для доставки (Unwheeled flow) |
| Work Center (JDE) | Select с поиском | Нет | Один WC на тип. Справочник Work Centers (коды: LRG, MGT, BHOE, DTRK...). Поле необязательное для Logistics |
| Порядок отображения | Number input | — | Авто-заполняется при создании (конец списка). Редактируемо вручную |

**Подсказка под полем «Требует транспортировку»:** «При включении Requestor получит уведомление о необходимости организации транспортировки»

---

### 3.3 Блок B: Специфические параметры (динамические характеристики)

Администратор задаёт набор динамических атрибутов для данного типа техники. Параметры **автоматически** появятся:
- в карточке техники (если isVisibleInCard = true)
- в форме заявки Requestor-а
- в фильтрах поиска (если isFilterable = true)

**Подзаголовок блока:** «Специфические параметры»

**Подсказка-описание под подзаголовком:** «Параметры автоматически отображаются в карточке техники, форме заявки и фильтрах поиска Requestor-а — в зависимости от выбранного типа техники»

#### Таблица добавленных параметров

| Колонка | Источник | Описание |
|---------|----------|----------|
| ≡ | sortOrder | Drag handle для изменения порядка внутри типа |
| Название параметра | Properties.name | |
| Ед. измерения | MeasurementUnits.displayName | «—» если тип значения не требует единицы |
| Тип значения | Properties.dataType | Русское название — см. п. 5.2 |
| Допустимые значения | PropertyEnumValues | Только для типа «Перечисление». Показать первые 3 значения + «...ещё N» / кнопка «Просмотреть» |
| Обязательный | isRequired | Чекбокс (можно изменять прямо в таблице) |
| Фильтруемый | isFilterable | Чекбокс. Tooltip: «Параметр появится как фильтр в поиске» |
| Видим в карточке | isVisibleInCard | Чекбокс. Tooltip: «Параметр отображается в карточке техники» |
| Действия | — | Редактировать (иконка карандаш) / Удалить (иконка корзина) |

**Пустое состояние блока B** (параметров нет):
- Текст: «Специфические параметры не добавлены»
- Подсказка: «Добавьте параметры — они будут отображаться в карточке техники и фильтрах поиска»

#### Кнопки под таблицей (всегда видны)

- **«+ Добавить параметр»** — открывает модальное окно M-AP-01
- **«Добавить из другого типа»** — открывает модальное окно M-AP-02

#### Действие «Удалить» параметр из типа

- Если параметр использует **только этот тип** (нет других типов с тем же Properties) → удаляется без предупреждения (только из EquipmentTypeProperties)
- Если параметр используется в **других типах** → диалог: «Параметр "[Название]" также используется в: [список типов]. Удалить только для этого типа?» → Да / Отмена

## 4. Модальное окно M-AP-01: Добавление / редактирование параметра

**Открывается из:** AP-02 → «+ Добавить параметр» или иконка «Редактировать» у параметра в таблице

**Заголовок:** «Добавить параметр» / «Редактировать параметр»

### 4.1 Два таба

| Таб | Описание |
|-----|----------|
| **Новый параметр** | Создать новый параметр в общем справочнике Properties + добавить к текущему типу |
| **Из справочника** | Выбрать уже существующий параметр из Properties (переиспользование между типами) |

---

### 4.2 Содержимое модалки

**Секция «Параметр» (зависит от выбранного таба):**

*Таб «Новый параметр»:*
- Название параметра — text input, обязательно (Пример: «Объём ресивера», «Тип привода»)
- Тип значения — select, обязательно (см. п. 5.2)
- Единица измерения — select из справочника MeasurementUnits (показывается **только** если тип = «Число целое» или «Число дробное»)
- Допустимые значения — редактируемый список (показывается **только** если тип = «Перечисление»):
  - Поле ввода нового значения + кнопка «Добавить»
  - Каждое значение: текст + drag handle + кнопка удалить
  - Drag & drop для изменения порядка (sortOrder в PropertyEnumValues)
  - Минимум 2 значения для сохранения

*Таб «Из справочника»:*
- Поле поиска параметра — поиск по название в Properties
- После выбора:
  - Название — read-only (из Properties.name)
  - Тип значения — read-only (из Properties.dataType)
  - Единица измерения — read-only (из Properties.unitId → MeasurementUnits)
  - Допустимые значения (если enum) — read-only список (из PropertyEnumValues)
  - Пояснение: «Тип и единица заданы в справочнике. Для изменения создайте новый параметр»

**Секция «Настройки отображения» (одинакова для обоих табов):**

| Элемент | Поле БД | Описание |
|---------|---------|----------|
| Обязательный | isRequired | Чекбокс. «Параметр обязателен при создании единицы техники» |
| Фильтруемый | isFilterable | Чекбокс. «Параметр будет доступен как фильтр при поиске техники» |
| Видим в карточке техники | isVisibleInCard | Чекбокс. «Параметр отображается в карточке единицы техники» |

**Кнопки:** Отменить | **Добавить** (при добавлении) / **Сохранить** (при редактировании)

## 5. Модальное окно M-AP-02: Импорт параметров из другого типа

**Открывается из:** AP-02 → «Добавить из другого типа»

**Заголовок:** «Импорт параметров из другого типа техники»

**Структура:**
1. **Выбор источника** — select / поиск по названию типа техники. В списке — все типы, кроме текущего
2. **Список параметров источника** (появляется после выбора типа):
   - Таблица с чекбоксами:
     | ☐ | Название | Ед. изм. | Тип значения | Обязательный | Фильтруемый | Видим в карточке |
     |---|----------|----------|-------------|-------------|------------|-----------------|
     | ☑ (заблок.) | Объём ресивера | л | Число дробное | ✓ | ✓ | ✓ |
     | ☐ | Рабочее давление | бар | Число дробное | — | ✓ | ✓ |
     | ... | | | | | | |
   - Параметры, **уже добавленные** к текущему типу: чекбокс отмечен и заблокирован, tooltip: «Уже добавлен»
   - Возможность выбрать все / снять всё
3. **Счётчик выбранных** над кнопками: «Выбрано: N параметров»

**Кнопки:** Отменить | **Добавить выбранные (N)** (primary, неактивна при N = 0)

**Поведение после добавления:** импортированные параметры наследуют настройки isRequired / isFilterable / isVisibleInCard из источника. Их можно изменить в AP-02 через таблицу или иконку «Редактировать».

## 5. Справочные данные

### 5.1 Типы мобильности (mobilityType)

| Код | Русское название |
|-----|----------------|
| SelfPropelled | Самоходная |
| NonSelfPropelledMotorized | Несамоходная моторизованная |
| Stationary | Стационарная |
| NonMotorized | Немоторизованная |

### 5.2 Типы значений параметра (dataType)

| Код | Русское название | Ед. измерения | Пример |
|-----|----------------|---------------|--------|
| number | Число целое | Да | Количество ступеней: 2 |
| double | Число дробное | Да | Объём ресивера: 500.5 л |
| text | Текст | Нет | Серийный номер двигателя |
| boolean | Да / Нет | Нет | Наличие обогрева |
| enum | Перечисление | Нет | Тип привода: Дизельный / Электрический |

### 5.3 Примеры единиц измерения (MeasurementUnits)

м, кг, кВт, л, бар, м³, т, км/ч, мото-ч — управляются в разделе «Справочники»

### 5.4 Примеры Work Center (коды JDE)

LRG, MGT, BHOE, DTRK, FTRK, GDRV, CRANE, FORKL, MLIFT, VTRK — управляются в разделе «Справочники»

## 6. Состояния и валидация

### 6.1 Общие состояния формы AP-02

| Ситуация | Поведение |
|----------|-----------|
| Форма не изменялась | Кнопка «Сохранить» неактивна |
| Обязательное поле пустое | Поле подсвечено красным, «Сохранить» заблокирована |
| Нажали «Отменить» с несохранёнными изменениями | Диалог: «Изменения не сохранены. Покинуть страницу?» — Остаться / Покинуть |

### 6.2 Удаление типа техники

| Условие | Результат |
|---------|-----------|
| К типу не привязана техника | Диалог подтверждения → удаление (soft delete) |
| К типу привязана техника (N единиц) | Кнопка «Удалить» заблокирована. Tooltip: «Нельзя удалить: к типу привязано N единиц техники» |

### 6.3 Удаление параметра из типа

| Условие | Результат |
|---------|-----------|
| Параметр используется только этим типом | Удаление без предупреждения |
| Параметр используется другими типами | Диалог: «Параметр "[Название]" также используется в: [список типов]. Удалить только для текущего типа?» |
