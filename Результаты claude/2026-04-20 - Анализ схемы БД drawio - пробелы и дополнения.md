# Анализ схемы БД Booking Tool (drawio) — пробелы и предложения по дополнению

**Дата:** 2026-04-20  
**Источник схемы:** `Документация в процессе работы с требованиями/2026-04-20/Booking tool.drawio.xml`  
**Источник требований:** BRD v7 (2026-04-20)

---

## 1. Текущее состояние схемы

### Таблицы в схеме

| Таблица | Описание | Состояние полей |
|---------|----------|-----------------|
| `BookingRequests` | Заявка (Request) | Проработана |
| `Bookings` | Бронирование (один RequestItem) | Проработана |
| `EquipmentId` | Единица техники | Только Id + FleetId — заготовка |
| `Fleet` | Флот | Только Id + FleetOwnerId — заготовка |
| `FleetOwners` | Флит-оунер | Только Id — заготовка |
| `BookingRequestsHistory` | История заявок | Только Id + BookingRequestId — заготовка |
| `BookingsHistory` | История бронирований | Только Id + BookingId — заготовка |
| `BookingFeedBack` | Отзывы на бронирование | Только Id + BookingId — заготовка |

### Связи в схеме

- `BookingRequests` → `Bookings` (1:many) ✅
- `BookingRequests` → `BookingRequestsHistory` (1:many) ✅
- `Bookings` → `EquipmentId` (many:1, mandatory) ✅
- `Bookings` → `BookingsHistory` (1:many) ✅
- `Bookings` → `BookingFeedBack` (1:many) ✅
- `Fleet` → `EquipmentId` (1:many) ✅
- `FleetOwners` → `Fleet` (1:many) ⚠️ — см. ниже: нужна M2M

## 2. Пробелы — поля, которых не хватает в существующих таблицах

### 2.1 `BookingRequests` (Заявка)

**Текущие поля:** Id, Type, Status, WorkOrderId, Location, Priority, RequestorId, CreatedAt, CreatedUserId, UpdatedAt, UpdatedUserId, DeletedAt, DeletedUserId

**Добавить:**

| Поле | Тип | Обоснование (BRD) |
|------|-----|-------------------|
| `WorkCenterId` / `WorkCenterCode` | FK / string | Work Center обязателен для JDE-флотов, опционален для Logistics (FR-NEW-12, FR-NEW-51) |
| `WorkOrderName` | string | Наименование WO — отображается из DataLake (Section 5.3.2) |
| `WorkOrderStatus` | string | Статус WO из JDE/DataLake |
| `WorkDescription` | string (~50) | Обязательное поле "Описание работ" (FR-NEW-13) |
| `Comments` | string | Необязательный комментарий от Requestor (FR-NEW-14) |
| `IsDefaultWorkOrder` | bool | Флаг "Default WO" для не-JDE пользователей (FR-NEW-51) |
| `IsDefaultWorkCenter` | bool | Флаг "Default WC" для не-JDE пользователей (FR-NEW-51) |

| `UpdatedAt` | datetime | Аудит |

## 4. Архитектурные замечания

| # | Проблема | Рекомендация |
|---|----------|--------------|
| 1 | Таблица называется `EquipmentId` (некорректно) | Переименовать в `Equipment` |
| 2 | `FleetOwnerId` как единственный FK в `Fleet` | Заменить M2M таблицей `FleetFleetOwner` |
| 3 | `BookingRequestsHistory` / `BookingsHistory` — пустые заготовки | Заполнить полями аудит-лога (см. п. 2.6) |
| 4 | Нет связи между `Fleet` и `FleetOwners` через таблицу | Добавить `FleetFleetOwner` |
| 5 | Отсутствует таблица `WorkOrders` | Нужна для кэша JDE WO (FR-NEW-48) и SWR |
| 6 | Нет справочников в схеме | Добавить handbook-таблицы (FR-NEW-50) |
| 7 | Департамент определяется по Equipment, не по FO | Поле `DepartmentId` должно быть в `Equipment` (OQ-NEW-J ✅ CLOSED) |
