# TCO HDV/HDE Booking Tool — Инициализация проекта

> Дата: 2026-04-03
> Тип анализа: Бизнес-анализ и системный анализ (/init)

## Контекст и домен

**Клиент:** TCO (Tengizchevroil) — нефтедобывающее предприятие в Казахстане.
**Проект:** Инструмент бронирования тяжёлой техники и оборудования (HDV — тяжёлые грузовые автомобили, HDE — тяжёлое промысловое оборудование).
**Стадия:** Сбор требований (ведутся встречи с заказчиком с марта 2026).
**Владелец процесса:** Департамент Логистики TCO.

---

## AS-IS: Текущее состояние

### Как устроен процесс сейчас

```
Потребность в технике
       ↓
Operations создаёт Work Order в JDE E1
       ↓
Плановик (Planner) формирует план работ
       ↓
Графист еженедельно на пятнице распределяет технику (Power BI)
       ↓
Команды принимают "обязательства" в Excel (SharePoint)
       ↓
Согласование времени — день в день, по рации/устно
       ↓
Завершение брони — сообщают по рации или выясняют сами
```

### Параллельные каналы бронирования

| Тип техники | Система | Проблема |
|-------------|---------|----------|
| Собственная TCO | JDE E1 | Нет точного времени, только дата + часы |
| Арендованная (долгосрочная, БП) | DCT | Нет данных о доступности |
| Арендованная (разовая, БП) | DCT | Нет единого перечня |
| Попытка: Equipment Tool | Power Apps | Сложный, используется только владельцами флота |

---

## Ключевые боли бизнеса

1. **Нет единой system of records** — техника TCO в Excel-файлах, данных по БП вообще нет
2. **Нет видимости утилизации** — генераторы, компрессоры, световые мачты, ман-лифты не отслеживаются
3. **Конфликты бронирований** — одна техника закладывается на несколько команд в один день
4. **Расхождение план/факт** — заложили 1 час, использовали 4, или наоборот
5. **Нет прозрачности затрат** — сколько тратится на аренду внешней техники, неизвестно
6. **Децентрализованное согласование** — нет автоматической маршрутизации, всё через людей

## TO-BE: Целевой процесс (концепция)

```
Заявитель создаёт Request в системе
       ↓
Добавляет единицы техники (Booking per equipment)
       ↓
Система проверяет доступность + приоритизирует внутренний флот
       ↓
Заявка подаётся → маршрутизация на согласование автоматически
       ↓
Внутренний флот: Fleet Owner подтверждает/отклоняет
Внешний флот: CC Owner → Fleet Owner (BP)
       ↓
Система создаёт RWA в DCT (для внешних бронирований)
       ↓
Бронирование активно → трекеры передают данные в DataLake
       ↓
Завершение / досрочное завершение → обновление доступности
```

## Модель данных (ключевые сущности)

```
Request (заявка)
├── type: Regular | Service Work Request
├── status: Draft | Submitted | In Progress | Completed
└── Booking[] (бронирования)
    ├── equipment_id → Equipment
    ├── date_from / date_to
    ├── status: Draft | Submitted | Partially Confirmed | Confirmed |
    │          Rejected | Withdrawn | In Progress | Early Terminated | Completed
    └── cost_center (обязательно для внешнего флота)

Equipment (единица техники)
├── fleet_id → Fleet
├── tco_id, license, serial_number, category
├── usage_status: Shared | Shared with Conditions | Frozen
├── tracker_ids (IVMS, WIALON, Vega)
└── dynamic params (ЦЗ, локация, контакты, статус)

Fleet (парк)
├── type: Internal (TCO) | External (BP)
└── Fleet Owner → AAD group (internal) | BP account (external)
```

## Роли и права доступа

| Роль | Источник прав | Ключевые действия |
|------|--------------|------------------|
| Requestor | Все в сети TCO | Создание заявок, отзыв, продление, ранняя отмена (внешний флот) |
| RWA Initiator | AAD группа | Дополнительно: бронирование внешнего флота |
| Service Work Processor | AAD группа | Работа с SWR из JDE E1 |
| Fleet Owner (Internal) | AAD группа (per fleet) | Подтверждение/отклонение, замена техники, заморозка |
| Fleet Owner (External/BP) | Приглашение от Admin | Регистрация техники БП, согласование |
| CC Owner + DPA | PSWS + DOA | Согласование внешних бронирований |
| Administrator | AAD группа (Logistics) | Управление парками, шаблонами, пользователями, отчёты |

## Интеграционная архитектура

```
HDV/HDE Booking Tool
        │
        ├── JDE E1 ────────── Work Orders → SWR (import)
        │                     ← Статусы Шагов (обратная синхронизация)
        │
        ├── DCT ────────────── → Создание RWA / доп. соглашений
        │                     ← Данные трекеров БП (для сопоставления часов)
        │
        ├── PSWS ───────────── ← CC Owner info, email пользователей
        │
        ├── DOA ────────────── ← DPA info
        │
        ├── DataLake / PI ──── ← IVMS + WIALON трекеры (утилизация, GPS)
        │
        └── Azure AAD ──────── SSO, RBAC, AAD groups
```

## Нефункциональные требования

- **Доступность:** ≥ 99.5% uptime
- **Безопасность:** RBAC + SSO (корпоративная аутентификация)
- **Соответствие:** Хранение полной истории согласований/отклонений для аудита
- **Масштабируемость:** Внутренний + внешний флоты (БП)
- **Конфигурируемость:** Минимум hardcode — максимальный срок бронирования и другие параметры через панель администратора
