# Изменения BPMN на основе реестра требований
**Дата:** 2026-04-07
**Тип документа:** Анализ изменений / проектное решение
**Источники:** Реестр требований (2026-04-06), BPMN v2, Summary встреч 06.04

---

## Решение: два отдельных процесса

| Файл | Назначение | Категории техники |
|------|-----------|------------------|
| `equipment request process v3.bpmn` | Бронирование внутреннего флота | Cat 1 (собственная TCO) + Cat 2 (долгосрочная аренда) |
| `external fleet booking process v1.bpmn` | Бронирование внешнего флота | Cat 3 (on-demand, требует нового SR) |

Связь: в v3 при отсутствии внутренней техники система вызывает `external fleet booking process v1` через **Call Activity**.

## Часть 1 — equipment request process v3.bpmn (внутренний флот)

### Структурные ошибки v2, которые исправляются в v3

| # | Ошибка v2 | Исправление в v3 |
|---|-----------|-----------------|
| E-01 | `Event_1s5x21e` (24h) — IntermediateCatchEvent с 2 исходящими потоками (BPMN-invalid) | Заменить на **Timer Boundary Event (non-interrupting)** на задаче "Wait for FO response" |
| E-02 | `Event_10983c9` (48h) — IntermediateCatchEvent после 24h, оба в основном потоке | Заменить на **Timer Boundary Event (interrupting)** на той же задаче |
| E-03 | `Activity_1kzyrl8` "Auto-escalate to external" — dead-end (нет исходящих) | Подключить к Call Activity → `external fleet booking process v1` |
| E-04 | `Activity_1lqswie` "Reminder" — dead-end (нет исходящих) | После Reminder → вернуться к ожиданию (или просто End для уведомления) |
| E-05 | `Activity_14l78jo` "Route to CC Owner" — dead-end в System pool для Cat 1+2 | **Удалить** — CC Owner не нужен для Cat 1+2 (R-40) |
| E-06 | CC Owner pool целиком не нужен для Cat 1+2 | **Удалить** пул CC Owner |
| E-07 | External FO pool целиком — заменить на Call Activity | **Удалить** пул External FO, заменить Call Activity |
| E-08 | `Event_0vmp0fu` (Rejected, Requestor) получает 2 message flow (от Internal и External отказов) | В v3 только один источник — отказ Internal FO после исчерпания всех вариантов |
| E-09 | `Activity_0942iuk` "Open Justification window" — нет outgoing (dead-end) | Подключить: отправить сообщение Requestor-у → Requestor заполняет → идёт в Call Activity |

### Логические изменения по требованиям

| Требование | Что меняется |
|-----------|-------------|
| **R-33** — FO при отказе при наличии техники обязан написать причину | В FO pool: Reject → обязательный UserTask "Enter rejection reason" → отправить в System |
| **R-34** — Отказ одного FO не закрывает заявку | В System pool: после получения Reject → XOR: "Есть другие Internal FO?" → да: снова Publish to next FO; нет: эскалация на External (Call Activity) |
| **R-23** — 24h напоминание, 48h эскалация (настраиваемые) | Timer Boundary Events на задаче ожидания ответа от FO |
| **R-31** — Cat 1+2 — единый поток, Cat 3 — отдельно | Cat 3 выделен в отдельный файл, вызывается через Call Activity |
| **R-40** — CC Owner только для Cat 3 | CC Owner пул удалён из v3 полностью |

### Схема процесса v3 (текстовая)

```
[Requestor]
  StartEvent: Open request window
  → Task: Choose equipment type
  → Task: Specify booking period
  → Task: Set priority (P1–P4)
  → Task: Submit request
  → (сообщение в System)
  → IntermediateCatchEvent: Wait for decision
      ← либо: "Confirmed" (message от System)
      ← либо: "Rejected (no FO available)" (message от System)
      ← либо: "No internal fleet — need justification" (message от System)
  → [Confirmed] → EndEvent: Booking confirmed
  → [Rejected]  → Task: Create new request (или EndEvent)
  → [Need justification] → Task: Fill Justification window
                         → Task: Select cost center
                         → (сообщение → System)
                         → IntermediateCatchEvent: Wait for external result
                         → (подхватывается Call Activity result)

[Booking Tool System]
  → ReceiveTask: Receive request
  → Task: Check internal fleet availability (Cat 1 + Cat 2)
  → XOR Gateway: Free internal equipment?
      yes → Task: Publish request to Internal Fleet Owners
              [Timer Boundary non-interrupting 24h] → Task: Send reminder → вернуться к ожиданию
              [Timer Boundary interrupting 48h]     → Task: Auto-escalate → CallActivity: External booking
              [ReceiveTask: FO responded]
                → XOR: Confirmed / Rejected?
                    Confirmed → Task: Notify Requestor → Task: Update status → EndEvent
                    Rejected  → XOR: Other FO available?
                                   yes → Task: Publish to next FO (loop)
                                   no  → CallActivity: External booking process v1
      no  → Task: Notify Requestor (no internal fleet)
          → ReceiveTask: Receive Justification from Requestor
          → CallActivity: External booking process v1

[Internal Fleet Owner]
  → ReceiveTask: Receive request notification
  → Task: Review request (priority, period, equipment availability)
  → XOR Gateway: Confirm / Reject?
      Confirm → Task: Assign specific equipment unit
              → Task: Confirm mobilization / handover
              → (сообщение → System: Confirmed)
              → EndEvent
      Reject  → Task: Enter rejection reason (mandatory)
              → (сообщение → System: Rejected + reason)
              → EndEvent
```

## Часть 2 — external fleet booking process v1.bpmn (Cat 3)

### Пулы

| Пул | Роль |
|-----|------|
| Requestor | Ожидает результатов, выбирает оптимальный вариант |
| Booking Tool System | Маршрутизация, хранение статусов, уведомления |
| CC Owner | Согласовывает привлечение внешнего BP |
| Contract Specialist (Central Contract Group) | Ведёт процедуру подбора BP вне системы, вносит результаты |

### Схема процесса (текстовая)

```
[Запуск] ← вызывается как CallActivity из v3 (или через отдельный ввод)

[System]
  → Task: Receive Justification + Cost Center from Requestor
  → Task: Route request to CC Owner
  → (сообщение → CC Owner)

[CC Owner]
  → ReceiveTask: Receive request + Justification
  → Task: Review (business need, cost center, priority)
  → XOR: Confirm / Reject?
      Reject → Task: Enter rejection reason
             → (сообщение → System: CC Rejected)
             → EndEvent
      Confirm → (сообщение → System: CC Approved)
             → EndEvent

[System] (после CC Approved)
  → Task: Notify Contract Specialist
  → Task: Update status: "Pending external bid"
  → (сообщение → Contract Specialist)
  → ReceiveTask: Wait for bid results from Contract Specialist

[Contract Specialist]
  → ReceiveTask: Receive notification + request details
  → Task: Conduct external bid procedure (offline: DCT, emails, light bid)
  → Task: Enter bid results into system:
          - Bidder 1: total sum + mobilization date (anonymous)
          - Bidder 2: total sum + mobilization date (anonymous)
          - Bidder N: total sum + mobilization date (anonymous)
  → (сообщение → System: bids entered)
  → IntermediateCatchEvent: Wait for Requestor selection

[System] (после получения ставок)
  → Task: Notify Requestor: bids available
  → (сообщение → Requestor)

[Requestor]
  → ReceiveTask: Receive bid notification
  → Task: Review bid options (anonymous: Bidder 1/2/3 + sum + date)
  → Task: Select preferred option
  → (сообщение → System: selection)

[System]
  → Task: Send selection to Contract Specialist
  → (сообщение → Contract Specialist)

[Contract Specialist]
  → ReceiveTask: Receive selection
  → Task: Issue SR in DCT/SMART for selected BP
  → Task: Enter SR number into Booking Tool
  → (сообщение → System: SR number)

[System]
  → Task: Link SR number to booking record (R-38)
  → Task: Create RWA draft in DCT (R-42, ⚠️ Уточняется)
  → Task: Notify Requestor: booking confirmed
  → Task: Update booking status: Confirmed
  → EndEvent

[CC Rejected path in System]
  → Task: Notify Requestor: request rejected by CC Owner (with reason)
  → EndEvent
```
