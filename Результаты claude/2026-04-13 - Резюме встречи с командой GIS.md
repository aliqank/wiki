## 1. Цель встречи

Обсудить подход к интеграции ГИС-карты в Booking Tool (CR Dashboard): как технически будет работать встраивание, какие данные отображаются и как происходит матчинг.

---

## 2. Ключевые решения и договорённости

### 2.1 Архитектура интеграции — Embedded-карта через URL-параметры

- Карта будет встроена (embedded) в интерфейс Booking Tool.
- Управление картой — через **URL-параметры**: фильтрация, приближение, отображение нужной техники.
- Кайсар отправил в чат **тестовую карту** — команда Booking Tool может уже начинать интеграцию и проверку.
- Со стороны GIS **нет технических ограничений** для интеграции; платформа гибкая и готова адаптироваться под логику Booking Tool.

### 2.2 Идентификация техники

- Каждая единица техники будет иметь уникальный **ID**.
- Этот ID будет **матчиться** с данными Booking Tool.
- Передача через URL: можно передавать как **один ID**, так и **массив/группу ID** (например, 4–5 единиц одновременно).
- Отображение на карте: при выборе техники — **приближение на карте + всплывающее окно** с деталями (последний сигнал, местоположение, назначение).
- **Подписи** (наименования техники, ГРЗ) будут отображаться в читаемом виде для пользователей, а не технические тестовые ID.

### 2.3 Данные и матчинг

- **Real-time данные** уже поступают (сейчас — только по LORAN; остальные источники в работе).
- **Мастер-данные техники** (характеристики, ГРЗ и др.) — хранятся в Booking Tool.
- Матчинг динамических данных с мастер-данными: через **Digital-команду (Айвар)** — либо on-the-fly, либо на backend-уровне (уточняет архитектор).
- Дополнительные данные в плашке техники: GIS-команда может получать их через **URL GET-метод** и отображать на карте.

### 2.4 Ожидания по следующим шагам

- GIS-команда **готова адаптировать** карту под логику Booking Tool, но для этого нужны **базовые бизнес-требования** (хотя бы прототип окна/экрана).
- Когда у команды появится первичное UX-видение — Кайсар настроит динамическую карту под конкретный экран.
- После формирования бизнес-требований по JDE-интеграции — **подключить команду GIS** к обсуждению (инициатор Диас).

## 3. Вопросы и ответы (Q&A)

| Вопрос | Ответ |
|--------|-------|
| Есть ли документация по текущим сервисам? | Кайсар отправил справочник по интеграции через URL в чат |
| Можно ли передавать массив ID техники? | Да, массив или группа — будет обсуждён оптимальный вариант |
| Откуда GIS берёт характеристики техники? | Из Booking Tool / Digital-команды (через матчинг); архитектор уточнит механизм |
| Можно ли добавлять кастомные данные в плашку на карте? | Да, через URL GET-метод |
| Можно ли настроить кастомные наименования (не технические ID)? | Да — после интеграции данных; сейчас тестовые ID без кастомизации |
| Есть ли портал/песочница с примерами карт? | Отдельного портала нет; Кайсар готов подготовить примеры под конкретный запрос |
| Можно ли получить доступ к существующему Dashboard? | Нет — он реализован в другой системе (ограниченный POC на ALPOL), не применим |

- **Бизнес-ожидание** сформировалось на основе демо ГИС-платформы (19 экранов с отчётностью, треками, утилизацией) — бизнес ожидает похожий UX: карта с маркерами техники и всплывающими окнами.

- **Текущий статус данных**: реальные данные, только LORAN; остальные датчики подключаются.
